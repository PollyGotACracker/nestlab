# 도구 규칙

이 문서는 tools의 목적과 고정 구조를 정의하는 기준 문서이다.
결함은 이 문서의 해당 항목과 실제 입력 및 동작을 대조해 판정한다.

## 결함 판정

- 구현 결함: 코드가 해당 항목의 목적이나 고정 구조와 다르게 동작한다.
- 시험 결함: 시험이 해당 항목의 목적이나 고정 구조와 다르게 기대한다.
- 기준 결함 후보: 해당 항목의 목적이나 고정 구조를 따르면 사용자가 의도한 결과가 나오지 않는다. 승인 전에는 보고만 한다.
- 도구의 설계와 기능 결함은 설계나 지침대로 동작하지 않는 경우, 사용자가 의도한 결과가 나타나지 않는 경우, 작업 중단 또는 번복이 잦아 능률을 심각하게 저해하는 경우이다. 판단과 그 근거를 보고한다.
- 구현 결함과 시험 결함은 판정한 턴에 수정한다.
- 고정 구조:의 변경과 기준 결함 후보의 수정은 변경 근거, 영향, 기존 동작과의 호환성을 보고하고 승인받은 뒤 수행한다.
- 목적이나 고정 구조가 모호하면 추측으로 수정하지 않고 사용자에게 보고한다.

## 개정 절차

1. 변경할 항목, 변경 내용과 변경 근거를 기록한다.
2. 영향받는 구성요소와 기존 동작의 호환성을 평가한다.
3. 사용자의 승인을 받는다.
4. 문서를 개정하고 변경 이력에 날짜와 내용을 추가한다.

## 도구 목록

### 지침 준수 검사

#### check_doc_rule

- 목적: 지침 문서의 끊어진 경로와 절 참조, 금지 패턴을 검사한다.
- 입력: 인자 없음(전체 대상 검사) 또는 `--hook`(PreToolUse 입력의 `Edit`, `Write`, `apply_patch` 쓰기 대상)
- 출력:
  - 전체 검사는 파일별 위반 수, `파일:행: [종류] 내용` 형식의 위반 줄, 종류별 합계를 stdout에 출력하고 위반이나 없는 대상이 있으면 종료 코드 1을 반환한다.
  - hook 모드는 쓰기 뒤 내용에 쓰기 전에 없던 위반이 있으면 위반 줄과 함께 거부하고, 위반이 없으면 출력하지 않는다.
  - hook 모드는 쓰기 뒤 내용을 계산하지 못하거나 오류가 나면 통과시킨다.
- 고정 구조:
  - 검사 항목은 저장소 경로, 절 참조, Rule ID 패턴, 부정형 표현, 다른 지침 파일 참조, 스킬 본문의 역할명, 코드 주석의 작업 기록 식별자이다.

### 설치와 연결

#### set_hooks

- 목적: bashrc 블록 설치, 설정 원본 자리표시 채우기, 전역 설정 병합을 한다.
- 입력: 인자 `install`
- 출력:
  - 결과 줄(bashrc 블록, Claude 설정 hook 커맨드 수, Codex 설정과 규칙 수, `nestlab-task-docs` 실행 파일 설치 결과)을 stdout에 출력한다.
  - 실패하면 stderr에 사유를 쓰고 종료 코드 1을 반환하고, `install`이 아닌 인자는 사용법을 출력하고 종료 코드 2를 반환한다.
- 고정 구조:
  - Claude 설정은 이전 설치 항목 중 값이 같은 항목을 지우고 새 항목을 병합한다. 목록은 없는 항목만 추가한다.
  - Codex hook 표와 규칙은 마커 블록으로 교체한다.
  - Windows에서는 Claude 설정에 sandbox 블록을 넣지 않는다.
  - 관리 표시가 있는 `nestlab-task-docs` 실행 파일만 갱신하고 알 수 없는 기존 파일은 보존한다.

#### set_skills

- 목적: 공용 skill 원본을 사용자 전역 skill 폴더에 연결하고 연결 상태를 확인한다.
- 입력: 인자 `check`, `link`, `unlink` 중 하나
- 출력:
  - 위치별 연결 상태와 연결 건수를 줄 단위로 stdout에 출력한다.
  - check는 모두 연결됨이 아니면, link와 unlink는 충돌이나 실패가 있으면 종료 코드 1을 반환한다. 잘못된 인자는 사용법을 출력하고 종료 코드 2를 반환한다.
- 고정 구조:
  - check는 파일을 바꾸지 않는다.
  - link는 빈 자리에 링크를 만들고 원본이 없어진 공용 링크를 지운다.
  - unlink는 공용 원본을 가리키는 링크와 원본이 없어진 링크를 지운다.
  - 실제 폴더와 다른 곳을 가리키는 링크는 그대로 둔다.

#### set_agents

- 목적: 프로젝트의 에이전트 원본 폴더를 사용자 전역 경로에 연결한다.
- 입력: 인자 `check`, `link`, `unlink` 중 하나
- 출력:
  - 연결 상태를 줄 단위로 stdout에 출력하고, 문제가 있으면 종료 코드 1을 반환한다.
  - 링크 생성은 OS 권한에 따라 실패할 수 있다. 실패하면 결과 줄에 오류를 출력한다.
  - 연결 대상은 Claude Code와 Codex의 agents 폴더이고, 설정 폴더가 없으면 건너뛴다.
  - 잘못된 인자는 사용법을 출력하고 종료 코드 2를 반환한다.

### 에이전트 작업

#### manage_task_worktree

- 목적: runner가 생성한 worktree의 변경 결과를 저장소 원본 checkout에 반영한다.
- 입력: apply 동작과 worktree 경로이고, 원본 경로는 생략하면 worktree에서 구한다.
- 출력:
  - 반영한 경로는 stdout, 보류한 경로는 stderr에 출력하고 보류가 있어도 종료 코드는 0이다.
  - 실패하면 원문과 종료 코드 1을 반환하고 원본과 worktree를 보존한다.
- 고정 구조:
  - 원본 내용이 기준 커밋과 다른 파일은 보류한다.

### 워크플로 작업

#### create_task_docs

- 목적: 독립 양식으로 작업 문서를 생성하거나 보고 양식을 출력한다.
- 입력: 작업 ID, 제목, 단계와 출력 프로젝트 또는 출력할 양식 이름
- 출력:
  - 새로 생성한 문서 경로 목록 또는 보고 양식 원문
- 고정 구조:
  - 구현 승인 요청 본문은 작업 문서 링크와 명세 요구사항 항목의 제목, 목표, 기대 결과, 한계, 잠재 위험 원문으로 구성한다.

#### run_incident_analysis

- 목적: 사건 문서의 분석을 별도의 director 세션으로 실행한다.
- 입력: 사건 문서 경로와 runner 이름(claude 또는 codex)
- 출력:
  - 성공하면 최종 메시지를 stdout에 출력하고 종료 코드 0을 반환한다.
  - 실패하면 사유와 수행할 행동을 stderr에 출력하고 종료 코드 1을 반환한다.
- 고정 구조:
  - 분석 세션은 hook을 끄고 실행한다.
  - Claude 분석 세션은 Bash를 거부하고 스킬, 문서와 웹 도구만 허용한다. Codex 분석 세션은 workspace-write 샌드박스로 실행한다.
  - 사건 문서 분석만 실행하고 조사와 반증의 단계 실행 경로는 두지 않는다.
