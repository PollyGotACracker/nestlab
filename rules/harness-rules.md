# 하네스 규칙

이 문서는 hooks의 목적과 고정 구조를 정의하는 기준 문서이다.
결함은 이 문서의 해당 항목과 실제 입력 및 동작을 대조해 판정한다.

## 결함 판정

- 구현 결함: 코드가 해당 항목의 목적이나 고정 구조와 다르게 동작한다.
- 시험 결함: 시험이 해당 항목의 목적이나 고정 구조와 다르게 기대한다.
- 기준 결함 후보: 해당 항목의 목적이나 고정 구조를 따르면 사용자가 의도한 결과가 나오지 않는다. 승인 전에는 보고만 한다.
- 하네스의 설계와 기능 결함은 설계나 지침대로 동작하지 않는 경우, 사용자가 의도한 결과가 나타나지 않는 경우, 작업 중단 또는 번복이 잦아 능률을 심각하게 저해하는 경우이다. 판단과 그 근거를 보고한다.  
  해당 하네스의 목적이 명확하다면 하네스 제거가 아닌 재설계를 목표로 둔다.
- 구현 결함과 시험 결함은 판정한 턴에 수정한다.
- 고정 구조:의 변경과 기준 결함 후보의 수정은 변경 근거, 영향, 기존 동작과의 호환성을 보고하고 승인받은 뒤 수행한다.
- hook 차단은 해당 hook의 목적과 고정 구조에 대조해 판정한다.
  입력이 그 목적에 해당하면 설계대로 차단한 것이므로 호출을 고쳐 다시 실행한다.
  입력이 목적에 해당하지 않으면 입력, 차단 문구, 대조한 항목을 기준 결함 후보로 보고하고 승인 전까지 hook을 그대로 둔다.
- 목적이나 고정 구조가 모호하면 추측으로 수정하지 않고 사용자에게 보고한다.

## 개정 절차

1. 변경할 항목, 변경 내용과 변경 근거를 기록한다.
2. 영향받는 구성요소와 기존 동작의 호환성을 평가한다.
3. 사용자의 승인을 받는다.
4. 문서를 개정하고 변경 이력에 날짜와 내용을 추가한다.

## 설계 규칙

- 하네스 코드의 저장소 경로는 경로 상수 파일에만 정의한다.
- 하네스는 기계 판정과 사전 차단을 우선하며 전체 역할의 영향을 확인한다.
  공통 보안과 director 메인 조정 검사를 구분하고 정상 입력의 허용도 검증한다.
- 하네스는 지침과 스킬을 참조하지 않고 독립적으로 기능하도록 설계한다.

## 하네스 목록

### 에이전트 실행

#### load_agent

- 이벤트: SessionStart, SubagentStart
- 목적: 에이전트 지침과 성향 원본 Markdown을 hook context에 주입한다.
- 출력:
  - 에이전트가 정해지지 않거나 알 수 없는 역할이면 출력하지 않는다.
  - 성향 문서, 에이전트 지침(`--include-role`이 있거나 실행 방식별 문서가 없을 때), 실행 방식별 문서(SessionStart는 MAIN.md, SubagentStart는 SUB.md) 순으로 출력한다.
  - director 메인 세션에는 작업 색인을 함께 출력하고, compact 뒤 첫 요청에는 현재 진행 작업의 마지막 `다음 작업` 줄을 출력한다.
  - 원본이 없으면 stderr에 오류를 쓰고 종료 코드 1을 반환한다.

#### show_statusline

- 이벤트: statusLine
- 목적: 에이전트 이름을 표시하고 Orca의 상태 정보 전송을 유지한다.
- 출력:
  - stdout에 `Agent: <이름>` 한 줄을 출력하고 종료 코드 0을 반환한다. 입력에 에이전트 이름이 없으면 `default`를 출력한다.
- 고정 구조:
  - 차단하지 않는다.
  - Orca 전달은 Orca 창(`ORCA_PANE_KEY` 환경 변수)에서 Windows이고 전달 스크립트가 있을 때만 동작한다.

### 비용 검사

#### check_context_size

- 이벤트: Stop
- 목적: 컨텍스트 기준에 도달한 메인 세션에 작업 기록과 compact 안내를 지시한다.
- 출력:
  - 기록이 필요하면 차단하고 안내를 출력하며, 나머지는 출력 없이 종료 코드 0을 반환한다.
  - 세션 기록을 읽을 수 없거나 토큰 정보가 없으면 통과시킨다.
- 고정 구조:
  - 기준은 200,000 토큰이다.
  - 서브에이전트 세션과 Stop hook이 이어서 실행한 Stop(`stop_hook_active`)은 검사하지 않는다.
  - 색인의 현재 진행 작업이 구현 단계이면 통과시킨다.

### 지침 준수 검사

#### check_invalid_response

- 이벤트: Stop
- 목적: 메인 에이전트 응답에서 실수와 위반을 인정하는 표현(직접 인정, 절차 및 검증 누락, 작업 번복, 반복 지적)을 찾아 사건 문서에 기록한다.
- 출력:
  - 감지하면 사용자 경고(감지 표현과 사건 문서 링크)를 표시한다.
  - Claude Stop은 차단하지 않고, Codex는 경고를 차단 사유로 출력한다.
    이유: Codex는 systemMessage를 대화 기록에 표시하지 않아 경고가 사용자와 에이전트에게 전달되지 않는다.
  - 기록 오류는 출력 없이 통과시킨다.
- 고정 구조:
  - 서브에이전트 응답은 검사하지 않는다.
  - 감지하면 사건 문서의 감지 기록 절에 감지 표현, 사용자 메시지와 응답 발췌를 기록한다.
  - 별도의 분석 세션은 직접 인정 유형이고 같은 사용자 메시지의 첫 감지일 때만 시작한다.
  - 사용자 메시지나 hook 사유에 있는 문장의 인용, 조건 설명, 부정 서술은 감지에서 뺀다.

#### check_response_quality

- 이벤트: Stop
- 목적: 응답의 예고, 책임 회피 표현, 한도를 이유로 한 작업 불가, 출처 없는 주장과 링크 없는 제안을 검사하고 응답을 다시 쓰게 한다.
- 출력:
  - 위반이면 응답을 차단하고 사유를 출력하며, 책임 회피 표현을 감지하면 감지 표현과 사건 문서 링크를 사용자 안내로 출력한다. 통과하면 출력하지 않는다.
  - Codex는 사용자 안내를 차단 사유에 담는다.
    이유: Codex는 systemMessage를 대화 기록에 표시하지 않는다.
- 고정 구조:
  - director 메인 세션의 응답만 검사하고, 구현 승인 요청 줄이 있는 응답과 사용자가 중단을 요청한 턴의 응답은 검사하지 않는다.
  - 책임 회피 표현은 사건 문서에 기록하되 분석 세션은 시작하지 않는다.
  - 백그라운드 작업이 남은 응답은 책임 회피 표현만 검사한다.
  - 한도 표현, 예고, 출처 없는 주장, 링크 없는 제안은 같은 턴에 한 번만 차단한다.
  - 오류는 통과시킨다.

#### load_incident_link

- 이벤트: UserPromptSubmit
- 목적: 미전달 사건 문서 링크를 에이전트에 주입한다.
- 출력:
  - 이 세션의 사건 문서 중 세션 기록에 링크가 없는 문서가 있으면 링크와 안내를 출력하고, 없으면 출력하지 않는다.
  - 사용자 메시지는 차단하지 않는다.
- 고정 구조:
  - 모든 역할에 주입한다.

### 권한

#### check_tool_use

- 이벤트: PreToolUse
- 목적: 작업 전 도구 사용을 검사해 위반 호출을 사전에 차단한다.
- 출력:
  - 위반이면 사유와 함께 차단한다.
  - 통과한 Claude 메인 세션 호출에 대기 중인 사용자 메시지가 있으면 도구 결과와 함께 전달하고, 그 밖의 통과는 출력하지 않는다.
  - 승인 창을 띄우는 ask는 출력하지 않는다.
- 고정 구조:
  - hooks/, tools/, shared/tools/ 아래 .py 파일에 쓰기 전에는 해당 상세 규칙 문서(hooks/는 rules/harness-rules.md, 그 밖은 rules/tool-rules.md)를 읽은 호출이 세션 기록에 있어야 한다.
  - runner가 stdin으로 넘긴 JSON을 해석하지 못하면 어떤 도구 호출인지 알 수 없으므로 출력 없이 통과시킨다.
  - JSON을 해석한 뒤 검사 중 오류가 나면 쓰기 도구(`Edit`, `Write`, `NotebookEdit`, `apply_patch`, 쓰기 `Bash`)는 deny하고 그 밖의 도구는 통과시킨다.
  - 대기 메시지와 같은 턴 재실행 검사는 Claude 메인 세션만 판정한다.
    이유: Codex는 hook 입력과 app-server에 대기 입력 정보가 없어 판정할 수 없다.

#### allow_approved_request

- 이벤트: PermissionRequest
- 목적: 사용자 승인 없는 자동 허용 범위를 세션별로 판정한다.
- 출력:
  - 질문 도구(`ExitPlanMode` 포함)는 출력 없이 runner 권한 판정을 따른다.
  - check_tool_use의 검사를 어긴 호출은 그 사유와 함께 거부한다.
  - 검사를 통과한 호출은 자동 허용한다.
  - git 쓰기 커맨드는 구현 담당(worker, documenter)의 단일 `git rm`, `git mv`, `git checkout --`만 판정한다.
    linked worktree에서는 허용하고 원본 checkout에서는 사유와 함께 거부하며, 그 밖의 git 쓰기는 출력 없이 승인 창을 유지한다.
  - 판정 중 오류는 검사 오류 사유와 함께 거부한다.
- 고정 구조:
  - 보안 위험과 외부 경로는 사전 검사와 runner의 deny 규칙이 담당한다.

### 워크플로 작업

#### record_workflow_stage

- 이벤트: UserPromptSubmit
- 목적: 사용자 메시지를 확인하여 작업 대상과 단계를 문서로 기록하고 지침을 전달한다.
- 입력: 사용자 메시지 머리줄 `[plan new]`, `[작업ID]`, `[plan|implement|complete]`, `[키워드 작업ID]`
- 출력:
  - 머리줄의 단계 키워드를 대상 작업의 경과 문서에 기록하고, 기록 결과 또는 기록하지 못한 사유를 추가 맥락으로 출력한다.
  - 머리줄 형식 안내, 작업 문서 없음 안내, 현재 진행 작업이 없을 때의 작업 선택 안내와 미완료 작업 목록을 출력한다.
  - 현재 진행 작업이 계획 단계이면 계획 단계 지침을 출력한다.
  - 사용자 메시지는 차단하지 않고, 출력할 내용이 없거나 오류가 나면 출력하지 않는다.
- 고정 구조:
  - 작업ID 없는 키워드는 작업 색인의 현재 진행 작업을 대상으로 한다.
  - 사용자 메시지가 승인이고 직전 응답에 구현 승인 요청 줄이 있으며 작업 문서가 승인 요청 검사를 통과하면 구현 승인과 구현 단계를 기록한다.
  - 사용자 메시지마다 작업 폴더의 경과 문서로 작업 색인을 다시 구성한다.
  - 색인 재구성, 단계 기록과 계획 지침은 director 메인에만 적용한다.

#### record_task_state

- 이벤트: PostToolUse
- 목적: 도구 호출 뒤에 질문 도구 답, 작업 단계와 사용자 승인 시각을 경과 문서에 기록하고, 작업 문서의 HTML 주석을 지운 뒤 작업 색인을 갱신한다.
- 입력: 도구 호출의 입력과 결과. Claude는 `Edit`, `Write`, `AskUserQuestion`, Codex는 `apply_patch`, `request_user_input` 호출 뒤에 실행한다.
- 출력:
  - 사용자 승인 시각을 확인하지 못했을 때만 출력한다. 이 hook이 경과 문서(status.md)의 `사용자 승인 시각` 줄에 `기록 없음`을 써 두었다는 사실과 그 문서 경로를 systemMessage로 사용자에게 알린다.
  - 그 밖에는 출력하지 않는다.
- 고정 구조:
  - 사용자 승인 시각은 사용자 메시지의 timestamp를 경과 문서의 승인 범위 절(계획 단계는 조사 승인 범위, 구현 단계는 구현 승인 범위)의 `사용자 승인 시각` 줄에 기록한다. timestamp를 확인하지 못하면 그 줄을 `기록 없음`으로 쓴다.
  - 프로젝트 세션에만 적용한다.
  - 질문 도구 답, 작업 단계와 사용자 승인 시각 기록은 director 메인에만 적용한다.
  - 작업 문서의 HTML 주석 삭제와 작업 색인 갱신은 director 외 프로젝트 세션에도 적용한다.
  - 도구 호출을 차단하지 않는다. 오류는 출력 없이 통과시킨다.

#### check_workflow_response

- 이벤트: Stop
- 목적: 응답의 양식, 구현 승인 요청, 완료 판정과 경과 문서의 작업 흐름 위반을 검사하고 응답을 다시 쓰게 한다.
- 출력:
  - 위반이면 응답을 차단하고 사유를 출력하며, 통과하면 출력하지 않는다.
  - Codex는 사용자 안내를 차단 사유에 담는다.
    이유: Codex는 systemMessage를 대화 기록에 표시하지 않는다.
  - 구현 승인 요청 줄은 검사를 통과하면 Claude에서는 show_approval_request가 본문으로 바꿔 표시하고, Codex에서는 본문을 차단 사유로 표시한다.
    이유: Codex hook 이벤트에는 MessageDisplay가 없다.
- 고정 구조:
  - 작업 흐름 검사는 director 메인에만 적용하고, 그 밖의 프로젝트 세션은 응답 양식 검사만 적용한다.
  - 같은 사유의 작업 흐름 위반이 연속으로 반복되면 경과 문서에 미해결로 기록하고 통과시킨다.
  - director 메인 Stop에서 질문 도구 답과 사용자 승인 시각을 경과 문서에 한 번 더 기록한다. 기록 방식은 record_task_state와 같다.
  - 오류는 통과시킨다.

#### show_approval_request

- 이벤트: MessageDisplay
- 목적: 작업 흐름 검사를 통과한 응답의 `구현 승인 요청: <작업 ID>` 줄을 hook이 생성한 승인 요청 본문으로 바꿔 표시한다.
- 입력: 응답의 표시 조각(delta), 마지막 조각 여부, 메시지 ID, 세션 기록 경로
- 출력:
  - 마지막 조각 전까지는 빈 내용을 표시하고, 마지막 조각에서 누적한 응답 전체를 표시한다.
  - 작업 흐름 검사를 통과하고 승인 요청 줄이 있으면 그 줄을 생성한 본문과 승인 안내 문장으로 바꾼다.
  - 작업 흐름 검사에 걸리거나, 승인 요청 줄이 없거나, 본문 생성에 실패하거나, 오류가 나면 원문을 표시한다.
  - 도구 호출 앞의 중간 메시지는 검사 없이 원문을 표시한다.
  - 완료 알림이 없는 백그라운드 작업이 있는 세션은 완료 판정을 건너뛴다.
- 고정 구조:
  - director 메인 세션만 바꾸고, 다른 역할은 조각을 그대로 표시한다.
  - 대화 기록의 응답 원문은 바꾸지 않는다.
  - Claude에서만 동작한다.
    이유: Codex hook 이벤트에는 MessageDisplay가 없다.

#### save_subagent_result

- 이벤트: SubagentStop, Stop(메인 세션)
- 목적: researcher의 최종 결과를 조사 문서에, reviewer의 반증 결과를 반증 문서의 회차 결과 절에 저장한다.
- 입력: 서브에이전트 보고(SubagentHandback으로 넘긴 보고, 없으면 마지막 응답)
- 출력:
  - 저장하면 출력하지 않는다.
  - 보고가 결과 템플릿의 블록과 칸을 모두 채우지 않았거나 보고가 비어 있거나 저장할 문서가 없으면 종료를 차단하고 사유를 출력한다.
  - reviewer의 검증 및 재검증 보고에서 실제 동작 PASS 항목에 실행 커맨드 근거가 없으면 저장하지 않고 차단한다.
  - 저장 중 오류가 나면 오류 이름과 함께 차단하고 보고를 다시 제출하게 한다.
- 고정 구조:
  - 보고는 결과 템플릿의 블록과 칸을 모두 채웠을 때만 절 본문으로 삽입한다.
  - 조사 결과의 주장 목록은 반증 문서의 주장 목록 절에 저장한다.
  - 칸 검사는 빈 값과 자리표시자만 판정하고 내용의 정확성은 판정하지 않는다.

#### save_subagent_report

- 이벤트: PreToolUse(서브에이전트 보고 반환)
- 목적: researcher 보고를 조사 문서에, reviewer 반증 보고를 반증 문서에 저장하고 보고를 경로 한 줄로 바꾼다.
- 출력:
  - researcher의 보고와 reviewer의 반증 보고를 문서에 저장하면 허용하고, 보고를 문서 경로와 저장 위치를 알리는 한 줄로 바꿔 전달한다.
  - 보고가 비어 있으면 거부한다.
  - 저장할 조사 문서나 반증 문서가 없으면 문서 경로와 함께 거부한다.
  - 보고가 템플릿을 지키지 않으면 거부한다.
  - 저장 중 오류가 나면 오류 이름과 함께 거부하고 보고를 다시 제출하게 한다.
  - 이미 저장된 보고, 작업 ID나 조사 문서 경로 줄이 없는 호출, director가 배정하지 않은 호출과 researcher, reviewer의 반증 보고가 아닌 호출은 바꾸지 않고 통과시킨다.
- 고정 구조:
  - 저장 형식만 검사하고 보고 원문의 사실 여부는 판정하지 않는다.

#### return_subagent_path

- 이벤트: PostToolUse
- 목적: researcher와 reviewer 호출 결과를 조사 문서와 반증 문서의 경로 한 줄로 바꾼다.
- 출력:
  - director 메인 세션이 완료 상태로 받은 호출 결과가 문서에 저장된 보고와 일치할 때만 바꾸고, 바꿀 것이 없거나 오류가 나면 출력하지 않는다.
  - Claude는 도구 결과를 직접 교체하고, Codex는 차단 사유로 도구 결과를 대체한다.
    이유: Codex PostToolUse는 도구 결과를 직접 교체하는 출력 필드를 지원하지 않고, decision이 block이면 hook 피드백이 도구 결과를 대체한다.
