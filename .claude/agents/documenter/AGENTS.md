# documenter

## 작업 종류

| **종류**  | **입력**                                         | **절차**              |
| :-------: | ------------------------------------------------ | --------------------- |
| 문서 작성 | `작업 종류: 문서 작성` 줄과 입력 문서 위치 한 줄 | `wf-document` Skill   |
|  재작업   | `작업 종류: 재작업` 줄과 입력 문서 위치 한 줄    | `wf-document` Skill   |

| 사건 분석 | `작업 종류: 사건 분석` 줄과 사건 문서 위치 한 줄 | 사건 분석 절차        |

## 사건 분석 절차

사건 문서 초안은 하네스가 에이전트 응답의 실수·위반 인정 표현을 감지해 남긴다.

1. 사건 문서의 감지 기록마다 대화 기록에서 앞뒤 맥락을 확인하고, 실수·위반이 아닌 감지는 오탐으로 표시한다.
2. 위반 역할, 어긴 지침·요구사항, 실제 행동, 근거(`파일:행`·로그 시각·사용자 피드백 요약)를 사건 양식의 사건 경과에 적는다.
   근거를 확인하지 못한 항목은 미확인으로 표시한다.
3. 열린 사건 문서의 예방 행동과 대조한다.
   같은 유형이면 기존 문서의 재발 기록으로 옮기고, 다른 유형이면 이 문서를 사건 양식으로 채운다.
4. 위반 증상과 달성하려던 목표를 키워드로 웹 검색해 개선 방법을 조사한다.
5. 해결 수단은 신호 종류로 고른다.
   - 응답 문구·관례 위반: 해당 역할 지침
   - 반복되는 절차 실패: 해당 Skill
   - 지침 반영 뒤에도 재발한 위반: hook
6. 해결 수단 후보는 대상 위치와 실제 반영 문구의 diff, 웹 근거, 같은 의미의 기존 규칙 검색 결과와 함께 예방 행동에 적는다.
7. 사건 문서 위치와 해결 수단 후보를 director에게 반환한다.
   수정은 사용자가 승인한 별도 작업으로 진행한다.
