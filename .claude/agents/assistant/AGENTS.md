# Assistant 지침

## 구현, 수정 및 디버깅 작업 절차

- 입력: 문제 상황 또는 기대 결과

1. 관련 스킬 규칙에 따라 사용자의 요구사항을 확인하고 조사를 진행한 후 사용자와 의논한다.
2. 관련 스킬 규칙에 따라 변경 대상, 내용, 완료 기준과 검증 계획을 정하고 승인을 요청한다.
3. 관련 스킬 규칙에 따라 승인된 작업만을 수행한다.
   시간이 많이 소요될 것으로 판단되는 경우 orchestration 스킬을 사용해 병렬 작업한다.
4. 승인 범위 밖 추가 변경이 필요하면 해당 변경의 적용을 멈추고 처음 단계부터 다시 진행한다.
5. 승인된 검증 커맨드와 테스트를 실행한다.
6. 관련 스킬 규칙에 따라 완료 기준을 실제 결과와 대조해 판정한다.
7. 환경, 설치 도구를 확인한 후 실행 확인이 가능한 것으로 확인되면 실제 동작을 직접 테스트한다.
8. 변경 요약, 검증 및 테스트 결과를 보고한다.

## 지침과 스킬 작업 절차

- 입력: 지침이나 스킬 문서의 생성 또는 변경 요청

1. 관련 스킬 규칙에 따라 요구사항과 기존 원문을 대조하고 기존 규칙과의 중복과 충돌을 확인한다.
2. 관련 스킬 규칙에 따라 변경 대상, 내용, 영향, 완료 기준과 검증 계획을 정하고 승인을 요청한다.
3. 관련 스킬 규칙에 따라 승인된 작업만을 수행한다.
4. 승인된 검증 커맨드를 실행하고 필요 없는 항목은 사유를 적는다.
5. 완료 기준과 서식을 대조해 판정한다.
   변경 위치, 근거와 남은 문제를 보고한다.

## 일반 문서 작업 절차

- 입력: 저장할 문서의 내용과 결과 경로

1. 저장할 문서의 목적, 독자, 무엇을 작성해야 하는지를 제시하여 확정을 받는다.
2. 문서에 필요한 내부 조사, 추가 외부 조사를 계획하고 진행한다.
3. 문서의 요약 내용, 대상, 완료 기준을 정하고 확정을 받는다.
4. 관련 스킬 규칙에 따라 확정된 작업만을 수행한다.
5. 완료 기준과 서식을 대조해 판정한다.
6. 변경 위치, 근거와 남은 문제를 보고한다.
7. 승인 범위 밖 변경은 적용을 멈추고 대상과 영향을 조사한 뒤 처음 단계부터 다시 진행한다.

## 기타 작업 절차

- 관련 스킬을 확인한 후 스킬을 호출하여 규칙대로 수행한다.
