# 프로젝트 README 작성

## 인수

- `대상`: 조사할 저장소 또는 하위 프로젝트
- `결과`: 대화의 초안 또는 작성할 README 파일 위치
- `독자`: 사용자, 개발자, 기여자 중 요청과 기존 문서에서 확인한 독자

## 절차

1. 대상을 확인한다.
	- 요청과 기존 README에서 대상, 독자, 언어와 결과 위치 확인
	- 결과에 영향을 주는 필수 정보가 빠지면 필요한 이유와 함께 질문
2. 저장소를 조사한다.
	- 기존 문서, 패키지 선언, 실행 설정, 진입점, 테스트와 CI 확인
	- 목적, 주요 기능, 요구 환경, 설치와 실행 명령 정리
	- 아래 환경변수 기준에 따라 예제 파일 검색과 코드 대조
	- 생성물과 의존성 폴더 제외, 설치 도구 확인에 필요한 lockfile 포함
	- 확인한 사실은 파일과 행 번호로 기록하고 기존 README와의 차이를 정리한다.
	- 운영 정책은 사용자에게, 외부 기술 정보는 해당 버전의 공식 자료에서 확인한다.
3. 목차를 정한다.
	- 기본 내용: 프로젝트 목적과 대상, 주요 기능, 시작 방법, 사용 예시와 기대 결과
	- 추가 내용: 화면, 개발, 구조, 문제 해결, 지원, 기여, 라이선스와 제한 중 필요한 항목
	- 서비스 이용, 패키지 사용과 저장소 개발은 각각 필요한 시작 방법을 안내한다.
	- 문서 및 설정 저장소는 자료 탐색과 적용 방법을 안내한다.
	- 목차, 배지와 Roadmap은 필요한 경우에 포함하고 현재 기능과 계획을 구분한다.
4. README를 작성한다.
	- 아래 작성 기준에 따라 확인한 자료로 작성
	- 시작 방법: 요구 환경, 설치, 필수 설정, 실행, 첫 성공 결과 순서
	- 기존 문서: 유효한 정보와 링크 보존, 삭제 근거와 영향 확인
	- 초안은 대화에 제공하고 파일은 승인된 위치와 범위에 작성한다.
5. 내용과 명령을 검증한다.
	- 원본 대조: 명령, 환경변수, 사용 예시, 링크, 이미지, 라이선스와 지원 범위
	- 환경변수 대조: 예제와 코드 사용 항목, README 설정 안내의 일치 여부
	- 명령은 승인 범위 안에서 실행한다.
	- 설치, 서비스 기동과 외부 전송의 영향은 실행 전에 확인한다.
6. 결과를 보고한다.
	- 작성 위치와 주요 변경
	- 실행 성공, 정적 확인과 미검증 항목
	- 남은 확인 사항

## 환경변수

1. .env.example, .env.sample, .env.template 등을 먼저 찾는다.
	- 숨김 파일과 하위 프로젝트도 포함한다.
2. 예제의 변수 이름, 설명과 안전한 예시값을 코드와 실행 설정에 대조한다.
	- 사용 위치: getenv, process.env, import.meta.env 등
	- 확인 항목: 검증 조건, 필수 여부, 기본값, 예제 누락과 미사용 변수
	- 예제가 없으면 코드와 설정에서 필요한 변수를 조사한다.
3. 실제 예제 경로와 설정 파일 생성 또는 복사 명령을 적는다.
	- 변수 정보: 이름, 용도, 필수 여부, 기본값과 안전한 입력 예시
	- 값 준비: 필요한 키 발급 위치와 외부 서비스 준비 방법
	- 적용 시점: 개발, 빌드와 실행의 차이, 재시작이나 재빌드 필요 여부
	- 예제가 없으면 코드와 설정에서 확인한 파일 위치와 생성 방법을 안내한다.
	- 필수 설정은 실행 전에 안내하고 추가 설정이 없으면 근거에 따라 생략한다.
4. 클라이언트 공개 값과 서버 전용 비밀값을 구분한다.
	- 실제 비밀값은 수집과 출력에서 제외하고 입력할 자리는 자리표시자로 쓴다.
	- 기존 설정 파일의 실제값은 보존한다.

## 작성 기준

### 1. 내용

- **소개**: 프로젝트 이름과 목적을 첫 부분에 배치
- **문체**: 짧은 소개와 항목은 명사구, 절차와 조건 설명은 완결 문장
- **기술 스택**: 공식 링크와 짧은 분류, 특별한 설계 판단과 호환 조건만 추가 설명
- **사실 확인**: 기능, 버전, 명령, 링크와 라이선스의 근거 확인
	- 미확인 항목은 질문하거나 확인 필요로 표시한다.
	- 가상 예시와 자리표시자는 실제로 확인한 사실로 대체한다.

### 2. 형식

- **목록**: 순서와 선행 의존이 있는 작업은 번호, 독립적인 정보는 글머리 기호
- **명령과 예시**: 실행 위치와 선행 조건, 셸별 차이, 언어를 지정한 코드 블록
- **문서 연결**: 내부 문서와 이미지는 상대 링크, 상세 문서는 요약과 링크
- **구조 설명**: 필요한 주요 항목만 tree로 표현

## 적용 사례

- 적용: 저장소를 조사해 처음 사용하는 사람용 README 작성
- 적용: 변경된 설치 방법에 맞춘 기존 README 갱신
- 비적용: GitHub 프로필 README 꾸미기
- 비적용: README에 나온 오류 디버깅
