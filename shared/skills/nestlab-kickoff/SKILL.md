# 작업 착수

## 착수 절차

### 1. 요청 확인과 이해 보고

1. 사용자 요청에서 해결할 문제, 요청한 결과물, 대상과 범위, 명시한 조건을 추출한다.
2. 사용자가 직접 정한 내용, 추가한 해석, 확인이 필요한 사항을 구분한다.
3. 요청을 어떻게 이해했는지 먼저 보고하여 사용자가 해석을 확인할 수 있게 한다.
4. 문서 작업은 독자와 용도를, 자료와 값에 관한 요청은 필요한 대상과 범위를 확인한다.
5. 사용자가 정한 완료 기준을 추출한다.
   별도 기준이 없으면 사용자가 명시한 요구사항을 기준으로 삼는다.
6. 초기 이해에 대한 수정 의견을 기존 기록 확인과 기초 조사에 반영한다.

### 2. 기존 기록 확인

1. 같은 요구를 다룬 기존 작업 기록을 찾는다.
2. 현재 상태와 남은 작업, 연결된 하위 문서를 전부 확인한다.
3. 기존 기록의 사실과 판단, 사용자 확정 사항을 원래 근거와 대조한다.
4. 확인한 근거가 현재 요청의 목표, 적용 조건과 버전에 맞으면 재사용한다.
5. 현재 요청과 달라진 내용, 부족한 근거와 충돌을 기초 조사 대상으로 정한다.
6. 추가로 확인할 항목마다 현재 요청과의 관련성과 조사 사유를 적는다.

### 3. 기초 조사

1. 저장소 목적과 설계 구조를 확인한다.
   - README, 프로젝트 전역 지침의 경로 목록과 컨벤션, 운영 문서 목차를 우선 읽는다.
   - 폴더 구조와 빌드 및 설치 설정 파일로 구성 요소와 진입점을 찾는다.
   - README와 문서 서술은 코드와 설정으로 확인할 주장으로 다룬다.
   - 요청 대상이 속한 구성 요소와 연결된 설치 도구, hook 등록 및 링크를 확인한다.
2. 실행 환경을 확인한다.
   - 세션 실행 위치와 적용 역할을 확인한다.
   - 설치된 지침, 에이전트와 스킬을 연결 도구의 확인 결과 및 링크 대상으로 대조한다.
   - 다른 실행 기록은 당시 실행 위치에서 열 수 있었던 경로와 주입된 지침으로 판정한다.
3. 요청 대상을 탐색한다.
   - 관련 구성 요소 안에서 대상 파일과 동작 및 인터페이스 확인에 필요한 파일을 연다.
   - 큰 파일은 검색어, 기호와 행 범위로 나눠 읽고 잘리거나 빠진 부분을 추가로 읽는다.
   - 결론이 의존하는 정의, 연결 절차, 호출자와 호출받는 쪽을 함께 읽는다.
   - hook과 설정의 도구 입력은 각 runner의 실제 도구 정의 및 스키마와 대조한다.
   - 진입점부터 관련 동작을 끝까지 따라가 데이터 흐름을 확인한다.
   - 같은 기능의 구현이 여럿이면 현행, 이전 구현과 생성물을 근거와 함께 구분한다.
   - 이동 대상의 활성 참조와 링크를 확인하고, 연결 갱신 및 복구 방법을 조사한다.
4. 생성하거나 바꿀 파일의 기존 형식을 확인한다.
   - 같은 종류 파일의 형식, 용어와 컨벤션을 확인한다.
   - 기존 컨벤션과 적용 원칙이 충돌하면 충돌 내용과 영향을 보고한다.
   - 지침은 적용 조건, 행동과 판정 기준이 겹치는 규칙을 검색한다.
   - 새 문서를 제안하기 전에 같은 작업을 다루는 기존 지침과 스킬을 검색한다.
5. 출처와 이력을 확인한다.
   - 설정과 권한 항목을 저장소 원본, 설치 도구 생성분과 사용자 항목으로 구분한다.
   - 변경 이력과 설치 도구의 병합 규칙으로 항목의 출처를 확인한다.
   - 설치본과 원본의 차이, 원본 사이의 정책 차이를 구분해 기록한다.
   - 과거 상태는 해당 시점의 원본과 변경 기록으로 대조한다.
   - 결함과 부재를 판정하기 전에 대상의 처리 규정과 실행 환경을 확인한다.
   - 로컬 상태는 실제 파일과 명령 결과로 확인한다.
6. 영향 범위를 조사한다.
   - 영향받는 기능, 채널, 설정, 문서와 테스트
   - 기존 동작과의 충돌
   - 요구사항과 충돌하는 지침, 스킬, 코드와 설정
   - 승인 및 보안 경계
   - 명칭 충돌
   - 같은 대상 파일을 다루는 다른 작업의 확정 사항과 작성 기준
7. 필요한 로그와 재현 자료를 확인한다.
   - 실행 가능한 로그 수집 명령은 직접 실행한다.
   - 사용자 환경에서만 실행할 수 있는 명령은 대상과 필요한 이유를 설명해 제시한다.
8. 문서 갱신 대상을 확인한다.
   - 영향받는 운영 문서와 README를 본문 검색어로 검색한다.
   - 일치한 위치와 검색어를 기록하고, 일치가 없으면 사용한 검색어를 기록한다.
9. 확인 범위를 정리한다.
   - 읽은 파일과 행 범위, 검색어, 제외한 경로를 기록한다.
   - 확인한 사실과 추론, 미확인 사항을 구분한다.
   - 변경 대상과 관련 파일이 있으면 기존 흐름을 코드 블록으로 정리한다.
   - 기존 흐름에는 진입점, 호출자, 호출받는 쪽과 같은 데이터를 읽는 검사를 포함한다.
   - 기존 흐름의 각 줄에 확인한 파일과 행을 붙인다.

### 4. 조사 결과 보고와 논의

1. 사용자 요청과 기초 조사 사실을 대조해 문제 정의와 범위 초안을 작성한다.
2. 다음 내용을 구분해 보고한다.
   - 사용자 요청 요약
   - 기존 기록에서 확인한 사항
   - 기초 조사 사실과 출처
   - 문제 정의 초안
   - 대상과 범위
   - 완료 기준과 확인 방법
   - 추가한 해석
   - 미확정 사항
3. 조사 근거를 바탕으로 사용자와 논의한다.
4. 논의에서 추가 확인이 필요하면 필요한 기초 조사를 보충한다.
5. 추가 조사 결과를 보고하고 논의를 이어간다.
6. 논의 결과에 따라 문제 정의와 범위 초안을 수정, 추가하거나 구체화한다.
7. 사용자가 정한 완료 기준은 유지한다.
   추가하거나 변경하려는 기준은 제안으로 구분해 사용자 확인을 받는다.
8. 측정 방법이 없는 기준도 유지하고, 미측정 범위와 확인 가능한 대안을 보고한다.
9. 문제와 범위의 판단에 영향을 주는 잠재 위험과 한계를 함께 보고한다.

### 5. 문제와 범위 확정

1. 조사와 논의를 거친 문제 정의 및 범위 초안을 사용자에게 보고한다.
2. 일반 질문으로 문제 정의와 범위가 사용자 의도에 맞는지 확인받는다.
   질문은 `문제 정의 확인:`으로 시작하고 끝에 `(작업 <MMDD-HHMMSS>)`를 붙인다.
   도구 답이 비거나 실패하면 문제 정의와 범위를 미확정으로 유지한다.
   응답에 확인할 내용과 선택지 또는 자유 입력으로 답할 방법을 안내하고 사용자 답을 기다린다.
3. 수정 의견이나 추가 확인 사항이 있으면 기초 조사와 논의를 이어간다.
4. 합의된 내용에 사용자 확인을 받은 뒤 문제 정의와 범위를 확정한다.
5. 확정한 내용과 확인 시각, 사용자 답의 요약을 기록한다.
6. 사용자 지시와 추가 해석의 실제 근거를 구분해 기록한다.
7. 현재 조건에 맞는 저장소 사실과 확인 범위를 조사 문서에 기록한다.
8. 기존 흐름은 조사 문서의 기존 흐름 절에 기록한다.

### 6. 조사 필요 판정과 계획

1. 확정한 문제마다 이미 근거가 있는 내용과 추가 조사가 필요한 내용을 구분한다.
2. 조사할 질문과 후보를 비교할 판단 기준을 정한다.
3. 추가 조사 항목마다 연결된 문제와 조사 목적, 확인할 근거를 적는다.
4. 기초 조사로 확인한 사실과 본조사에서 확인할 원인 및 해결 후보를 구분한다.
5. 검증과 실측이 필요한 기준은 대상과 환경, 방법 및 관측할 결과를 정한다.
6. 대체 수단을 사용하면 원래 대상과의 차이 및 입증할 수 있는 범위를 설명한다.
7. 실측 계획에는 대상, 방법, 횟수와 예상 비용을 적는다.
8. 조사 계획에 영향을 주는 잠재 위험과 한계를 정리한다.

### 7. 착수 보고와 승인

1. 확정한 문제와 범위, 사용자 확인 근거, 완료 기준 및 조사 계획을 보고한다.
2. 관련 작업 문서의 경로와 확인할 절을 제시한다.
3. 조사 범위와 필요한 실측 계획, 잠재 위험 및 한계를 설명한다.
4. 착수 승인을 받으면 승인한 대상과 행동, 영향 범위 및 시각을 기록한다.
5. 착수 승인 뒤 확정한 범위의 원인과 해결 후보를 조사하는 단계로 넘어간다.

## 조사 규칙

- 기초 조사는 요청의 의미, 관측 사실과 문제 및 범위를 정하는 데 필요한 근거를 확인한다.
- 원인과 해결 후보의 비교 조사는 문제 및 범위 확정과 착수 승인 뒤 수행한다.
- 조사 중 얻은 사실과 추론, 미확인 사항은 출처와 함께 구분한다.
- 사용자와의 논의에서 새 확인 사항이 나오면 필요한 조사와 결과 보고를 반복한다.
- 확정된 문제나 범위의 변경은 근거와 영향을 보고하고 사용자 확인 뒤 반영한다.
- 사용자 항목으로 확인한 설정과 권한은 승인된 변경 범위에 따라 처리한다.
- 저장소 확인만 요청받으면 요청 범위의 기초 조사와 그 결과 보고를 수행한다.
- 문서를 쓸 권한이 없는 실행에서는 확인 범위와 결과를 응답으로 반환한다.

## 웹 조사 규칙

- 외부 사실이 필요한 조사에는 요청의 문제, 적용 상황과 목표를 검색어로 사용한다.
- 최초 검색어는 사용자가 언급한 대상, 상황과 목표로 작성하고 검색 전에 제시한다.
- 자료 유형은 확인할 내용에 맞춰 선택한다.
  - 기능과 명세: 공식 문서와 변경 기록
  - 사용 관행: 공개 구현과 운영 사례
  - 사용 빈도: 통계와 사용량 자료
  - 문제 원인: 이슈와 수정 기록
- 대상과 버전에 맞는 원문을 읽고 적용 조건과 갱신 시점을 확인한다.
- 별도 버전 조건이 없으면 최신 자료를 우선 확인한다.
- 상충하는 자료는 원문의 근거와 적용 조건을 대조한다.
- 근거가 부족하면 검색어와 자료 범위를 바꿔 추가 조사한다.
- 공식 원문에 명시된 옵션 이름, 기본값과 지원 여부는 원문으로 확인한다.
- 해결 후보의 적용 조건과 한계는 저장소 조건과 대조한다.
- 후보 비교가 필요한 단계에서는 대안과 추천하기 어려운 조건도 조사한다.

## 착수 규칙

- 초기 요청 이해는 사용자가 확인할 수 있도록 먼저 보고한다.
- 문제 정의는 사용자 요청과 기초 조사 사실로 초안을 만들고 논의와 사용자 확인 뒤 확정한다.
- 추가 해석은 사용자에게 보고하고 확인받은 뒤 확정 기록이나 구현 기준에 반영한다.
- 문제 이해 확인은 일반 질문으로, 조사 후 후보 선택과 추가 제안은 검토로 처리한다.
- 검토는 후보가 하나인 경우도 포함한다.
- 문제 및 범위 확인과 착수 승인은 각각의 절차로 처리한다.
- 착수 승인은 문제와 범위 확정 및 조사 계획 보고 뒤에 받는다.
- 실측은 실행 전에 대상, 방법, 횟수와 예상 비용을 보고하고 승인받는다.
- 기준의 변경과 제외는 사용자 승인 뒤 반영한다.
- 에이전트 행동 규칙의 변경은 역할과 실행 형태별 적용 대상 및 기존 절차와의 차이를 보고한다.
- 도구, 라이브러리와 서비스의 추천 후보는 필요한 기능, 호환성과 제약이 확인된 것으로 정한다.
- 추천 후보는 다음 지표의 확인값과 출처를 함께 정리한다.
  - 채택 규모
  - 커뮤니티 활동
  - 마지막 갱신
  - 이슈 종료 빈도
  - deprecated 여부
- 확인하지 못한 지표는 미확인으로 구분한다.

## Template

초안 보고에는 확인한 내용과 미확정 사항을 쓴다.
사용자 확인 뒤 확정 기록과 조사 계획을 채우고 착수 승인을 보고한다.

```markdown
## 착수 보고

- 보고 시점: <초안 논의 | 문제와 범위 확인 | 착수 승인>
- 문서: <작업 문서 경로>, 확인할 절: <절 이름>

### 요청 요약

- <사용자 요청의 핵심>

### 기존 기록

- <기존 상태와 확정 사항 및 현재 요청과의 차이>
- 근거: <파일:행 | 사용자 기록의 로그 시각>

### 기초 조사

- <확인한 사실과 출처>
- <추론과 근거>
- <미확인 사항과 확인 방법>

### 기존 흐름

<관련 파일이 있으면 파일:행을 붙인 흐름 코드 블록>

### 문제 정의

- 초안: <해결할 문제와 관측 사실>
- 확정 내용: <사용자 확인 뒤 확정한 내용 | 확인 전>

### 대상과 범위

- 대상: <파일과 동작>
- 범위: <이번 작업에 포함하는 내용>
- 경계: <다른 작업이나 별도 판단이 필요한 내용>

### 완료 기준

- <기준과 연결된 사용자 요구>
- 확인 방법: <대상, 방법과 관측할 결과>
- 미측정 범위와 대안: <내용 | 없음>

### 해석과 미확정

- 추가 해석: <요청에서 직접 정하지 않은 대상, 범위와 방식 | 없음>
- 미확정 사항: <추가 조사나 사용자 판단이 필요한 내용 | 없음>

### 논의 경과

- <조사 결과에 관한 사용자 의견과 반영 내용>
- 추가 조사: <필요한 사실과 조사 결과 | 없음>

### 사용자 확인

문제 정의 확인: <문제 정의와 범위가 사용자 의도에 맞는지 확인하는 문장> (작업 <MMDD-HHMMSS>)

- 확인 기록: <확인 전 | 사용자 확인 시각과 답의 요약>

### 조사 필요 판정

- 근거 있음: <확인한 항목과 출처>
- 근거 없음: <추가 확인이 필요한 항목 | 없음>

### 조사 계획

1. 조사 <번호>. <항목명> (문제 <번호>): <확인할 질문과 판단 기준>

### 실측 계획

- 대상: <실측 대상 | 해당 없음>
- 방법: <실행 방법>
- 횟수와 예상 비용: <횟수와 비용>

### 잠재 위험과 한계

- <판단 및 실행에 영향을 주는 내용과 확인 범위 | 없음>

### 착수 승인

- 상태: <승인 대기 | 승인>
- 승인 범위: <대상, 행동과 영향 범위>
- 승인 기록: <사용자 승인 시각 | 기록 없음>
```
