# 작업 착수

- 정보를 수집할 때마다 확인·추정 구분과 출처를 함께 적는다.
- 저장소 확인만 요청받으면 `4. 저장소 조사` 절과 `8. 결과 반환` 절의 저장소 항목만 적용한다.

## 절차

### 1. 요구 정리

1. 사용자 요구 원문을 요구 요약과 해석으로 나눈다.
   - 요구 요약: 사용자 요구의 핵심
   - 해석: 사용자 요구에 없는 대상, 범위와 방식
2. 해석은 사용자가 확인한 뒤에 요구사항에 넣는다.
3. 변경 제안을 만들 때는 제안하려는 변경을 요구 원문으로 보고 같은 조사를 마친 뒤 제안한다.
4. 에이전트 행동 규칙을 변경할 때 역할과 실행 형태별 적용 대상을 확인하고, 기존 절차와 달라지는 내용을 보고한다.

### 2. 완료 기준

1. 요구사항과 완료 기준 충족에 필요한 대상을 고르고, 대상마다 요청과의 관련성을 확인한다.
2. 완료 기준은 사용자가 정한 기준을 쓰고, 정한 기준이 없으면 사용자가 명시한 요구사항으로 정한다.
3. 측정 방법이 없는 기준은 유지하고 `미측정`으로 표시한 뒤 확인 가능한 대안을 제시한다.
   - 기준의 변경과 제외는 사용자 승인 후 반영한다.
4. 문서를 만들거나 바꾸기 전에 요청과 기존 문서에서 독자와 용도를 확인한다.
5. 외부 정보, 자료, 값은 요청한 범위를 확인한다.

### 3. 기존 기록 확인

1. 같은 요구로 이미 착수한 작업 기록을 확인한다.
2. 진행 중인 작업의 조사 문서 `프로젝트 환경`과 명세 문서 `읽기 범위`가 있으면 먼저 읽는다.
3. 확인된 값이 현재 요청의 목표, 적용 조건과 버전에 맞으면 재사용한다.
4. 변경, 누락, 충돌이 생긴 범위만 추가 조사 대상으로 적고 그 사유를 적는다.

### 4. 저장소 조사

1. 저장소 목적과 설계 구조를 확인한다.
   - README, 프로젝트 전역 지침의 경로 목록과 컨벤션, 운영 문서 목차를 우선 읽는다.
   - 폴더 구조와 빌드·설치 설정 파일로 구성 요소와 진입점을 찾는다.
   - README와 문서 서술은 코드와 설정으로 확인할 주장으로 다룬다.
   - 요청 대상이 속한 구성 요소와 그 구성 요소를 연결하는 설치 도구, hook 등록, 링크를 적는다.
2. 실행 환경을 확인한다.
   - 세션 실행 위치(cwd)와 역할을 확인한다.
   - 전역 폴더에 연결된 지침, 에이전트, 스킬은 Agents 연결 도구와 스킬 연결 도구의 `check` 결과와 링크 대상으로 확인한다.
   - 다른 세션의 기록을 판정할 때는 그 기록의 실행 위치에서 열 수 있었던 경로와 주입된 지침으로 판정한다.
3. 대상을 탐색한다.
   - 1번에서 찾은 구성 요소 안에서 요청 대상 파일과 그 동작·인터페이스 확인에 필요한 파일을 연다.
   - 확인 범위 지정이 없으면 파일 전체를 확인한다.
     큰 파일은 검색어, 기호, 행 범위로 나눠 읽고 빠지거나 잘린 부분만 추가로 읽는다.
   - 결론이 의존하는 정의, 연결 절차, 호출자와 호출받는 쪽을 함께 읽는다.
   - 진입점부터 동작 하나를 끝까지 따라가 데이터 흐름을 확인한다.
   - 같은 기능의 구현이 여럿이면 현행, 이전, 생성물을 근거와 함께 구분한다.
   - 파일을 옮기기 전 활성 참조와 링크의 실제 대상을 확인한다.
     기존 연결에 영향이 있으면 링크 갱신의 실행 가능 여부와 복구 방법을 확인한다.
4. 요청에 파일을 만들거나 바꾸는 작업이 있으면 기존 형식을 확인한다.
   - 같은 종류 기존 파일의 형식, 용어, 컨벤션을 확인한다.
     기존 컨벤션이 원칙과 충돌하면 작업 전 알린다.
   - 지침 문서는 같은 의미의 기존 규칙과 적용 조건, 행동, 판정 기준이 겹치는 위치를 검색한다.
   - 새 문서를 만들기 전 같은 작업을 다루는 기존 지침과 스킬을 검색한다.
5. 출처와 이력을 확인한다.
   - 설정과 권한 항목은 저장소 원본, 설치 도구 생성분, 사용자 항목 중 어디서 왔는지 `git log -S`와 설치 도구의 병합 규칙으로 확인한다.
   - 설치본과 원본의 차이는 원본끼리의 정책 차이와 다른 표로 나눠 적는다.
   - 과거 상태와 변경은 해당 시점의 원본과 기록(`git show <커밋>:<경로>`, `git log`)으로 대조한다.
   - 결함과 부재를 보고하기 전 대상 문서의 처리 규정과 실행 환경을 확인한다.
   - 로컬 상태는 실제 파일과 명령 결과로 확인한다.
6. 변경 영향 범위를 조사한다.
   - 디버깅 요청에서 필요한 로그가 없으면 수집 커맨드를 실행하고, 사용자 환경에서만 실행되는 커맨드만 제시한다.
   - 영향받는 기능, 채널, 설정, 문서와 테스트
   - 기존 동작과의 충돌
   - 요구사항과 충돌하는 저장소 지침, 스킬, 코드와 설정
   - 승인 및 보안 경계
   - 명칭 충돌
   - 영향받는 운영 문서와 README를 본문 검색어로 검색하고, 일치한 `파일:행`과 검색어를 문서 갱신 대상으로 적는다.
     일치가 없으면 사용한 검색어를 적는다.
   - 사용자 항목으로 확인된 설정과 권한 항목은 변경 대상에서 제외한다.
   - 같은 대상 파일을 다루는 진행 중이거나 중단된 작업의 확정 사항과 작성 기준을 확인한다.
7. 확인 범위를 기록한다.
   - 읽은 파일과 행 범위, 사용한 검색어, 검색에서 제외한 경로를 적는다.
   - 진행 중인 작업의 조사 문서가 있으면 확인한 저장소 사실과 확인 범위를 그 문서 `프로젝트 환경`에 추가한다.
     파일 쓰기 권한이 없는 세션은 결과의 확인 범위에 담아 반환한다.

### 5. 웹 조사

1. 다음 작업은 요청의 문제, 적용 상황과 주어진 목표를 검색어로 웹 검색한다.
   - 설계안과 아키텍처 검토
   - 기능 구현과 리팩터링 방식 선정
   - 오류 원인과 해결 방안 조사
   - 도구, 라이브러리와 서비스 비교 및 추천 안 선정
   - 설치, 설정과 외부 서비스 연동 방식 선정
   - 지침과 스킬의 절차 설계 및 변경
2. 대상과 버전에 맞는 공식 원문을 읽는다.
3. 해결 방식의 적용 조건과 한계를 저장소 조건과 대조한다.
4. 후보의 대안과 해당 후보를 추천 안으로 삼기 어려운 조건을 검색해 비교한다.
5. 공식 원문에 답이 있는 사실은 해당 원문을 직접 확인해 채운다.
   e.g. 옵션 이름, 기본값, 지원 여부
6. 도구, 라이브러리와 서비스를 추천 안으로 낼 때는 아래 지표마다 확인값과 출처를 적는다.
   - 채택 규모
   - 커뮤니티 활동
   - 마지막 갱신
   - 이슈 종료 빈도
   - deprecated 여부

### 6. 후보와 기준 조사

1. 도구 추천 후보는 사용 목적에 필요한 기능, 호환성, 제약이 확인된 도구로 한정하고 나머지 도구는 미확인으로 구분한다.
   - 수치 임계값은 사용자가 정한 경우에만 판정에 적용한다.
2. 검증과 실측 기준을 정할 때 실행 대상과 환경, 대체 대상, 관측할 결과와 근거가 입증하는 범위를 조사해 함께 제시한다.

### 7. 승인 준비

1. 파일과 폴더 이동은 원본과 목적지가 사용자 요청이나 승인에 포함되고, 확인한 참조와 링크의 갱신 방법이 승인 범위에 있을 때 수행한다.
   - 스킬 이름 선택의 승인은 이름에 한정한다.
   - 디렉터리 이동과 외부 링크 설치는 각각 대상, 행동, 영향 범위를 승인받는다.
2. 문서 삭제·이동 계획은 원본 절이나 행별 이동 위치를 대조표로 제시한다.
3. 모듈을 나누거나 함수를 옮기는 계획은 모듈별 담당 기능과 옮길 함수 대조표로 제시한다.

### 8. 결과 반환

1. 아래 항목을 반환한다.
   - 요구 요약과 해석 항목
   - 완료 기준과 측정 방법, `미측정` 기준의 대안
   - 핵심 파일 표: 파일, 구성 요소에서의 역할, 근거 `파일:행`
   - 저장소 사실과 `파일:행` 출처
   - 문서 갱신 대상
   - 채운 값과 확인·추정 구분
   - 검토 항목
   - 같은 대상 파일을 다루는 작업과 그 확정 사항 및 작성 기준
   - 요구사항과 충돌하는 지침, 스킬, 코드와 설정의 위치와 우선순위에 따른 처리
   - 미확인 항목과 그 확인 방법
   - 확인 범위와 읽지 않은 변경 대상
