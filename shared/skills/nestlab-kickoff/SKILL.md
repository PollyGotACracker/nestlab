# 작업 착수

## 절차

### 1. 조사

1. 사용자 요구 원문을 요구 요약과 해석으로 나눈다.
   - 변경 제안을 만들 때는 제안하려는 변경을 요구 원문으로 보고 같은 조사를 마친 뒤 제안한다.
   - 요구 요약: 사용자 요구의 핵심
   - 해석: 사용자 요구에 없는 대상·범위·방식을 항목마다 적는다.
     해석은 사용자가 확인한 뒤에 요구사항에 넣는다.
2. 같은 요구로 이미 착수한 작업 기록이 있으면 확인된 값을 재사용하고 변경·누락 범위만 추가 확인한다.
3. 변경으로 영향을 받는 기능·채널·설정·문서·테스트, 기존 동작과의 충돌, 승인·보안 경계, 명칭 충돌을 조사한다.
   - 저장소 탐색에서 찾은 운영 문서와 README 일치 `파일:행`과 검색어를 문서 갱신 대상으로 적는다.
   - 출처 확인에서 사용자 항목으로 확인된 설정·권한 항목은 변경 대상에 넣지 않고 질문 목록에 넣는다.
   - 같은 대상 파일을 다루는 진행 중이거나 중단된 작업의 확정 결정과 작성 기준을 확인하고, 새 요구와 다르면 질문 목록에 넣는다.
4. 디버깅 요청에서 로그가 없으면 수집 커맨드를 제시한다.
5. 대화와 저장소, 웹 검색으로 채울 수 있는 값을 먼저 채우고, 채운 값마다 확인·추정 구분과 출처를 적는다.

### 2. 질문과 반환

1. 채우지 못한 값, 추정으로 채웠고 요구·지침으로 정해지지 않는 값으로 나누어 질문 목록을 만든다.
   - 질문은 답에 따라 결과물이 달라지는 값으로 한정한다.
   - 질문마다 확인한 범위(도구와 결과)와 조사로 채울 수 없는 이유를 붙인다. 이유를 쓸 수 없으면 질문 대신 조사한다.
   - 권한·범위 규칙은 대상별 표로 다시 보여 주고 확인받는다.
2. 후보를 비교해 골라야 하는 항목만 외부 의존 결정 항목으로 고른다.
   - 공식 원문에 답이 있는 사실은 `1. 조사`의 5번에서 직접 확인해 채운다.
     e.g. 옵션 이름, 기본값, 지원 여부
3. 아래 항목을 반환한다.
   - 요구 요약과 해석 항목
   - 저장소 사실과 `파일:행` 출처
   - 문서 갱신 대상
   - 채운 값과 확인·추정 구분
   - 질문 목록
   - 외부 의존 결정 항목
   - 같은 대상 파일을 다루는 작업과 그 확정 결정·작성 기준
   - 확인 범위와 읽지 않은 변경 대상
