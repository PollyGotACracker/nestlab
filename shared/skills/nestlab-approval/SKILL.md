## 승인 요청 절차

1. 승인 종류에 맞는 양식을 생성기의 `--print-template <양식>` stdout으로 읽는다.
   - 조사 승인: `approval-research`
   - 모델 호출 실측 승인: `approval-measure`
   - 완료 승인: `approval-complete`
   - 구현 승인: 응답에 `구현 승인 요청: <작업 ID>` 한 줄만 쓴다.
     hook이 명세 문서로 생성한 승인 요청 본문을 사용자에게 표시하고, 사용자가 `승인`을 보내면 hook이 구현 승인과 구현 단계를 기록한다.
     Claude는 응답 표시에서 요청 줄이 본문으로 바뀐다. Codex는 Stop hook 안내로 본문이 표시되며, 안내가 지시한 확인 줄 한 줄만 이어서 쓴다.
     hook이 차단하면 사유에 적힌 작업 문서 칸을 채운 뒤 같은 한 줄을 다시 쓴다.
2. 작업 문서가 있는 작업에서는 확정된 내용과 확인할 사실을 구분해 작업 문서에 반영한다.
   사용자가 요구를 바꾸거나 새 지시를 준 턴에 반영하고 승인 요청을 이어서 작성한다.
3. 양식의 각 절에 변경 묶음 하나의 내용을 채우고 제목과 필드를 따른다.
   - 지침 문구 변경과 예상되는 표시나 결과의 변경 전후는 실제 원문과 대조한 unified diff로 붙인다.
   - 문구를 바꾸지 않고 위치만 옮기는 줄은 원본 절, 행과 이동 위치의 대조표로 붙인다.
   - 한계에는 설계 자체의 제약을, 위험에는 외부 이슈의 조건과 영향을 쓰고 `출처:`를 붙인다.
4. 번호와 이름 및 확정 결과를 명세와 대조하고 모든 필수 값과 작업 문서 링크를 확인한다.
   불일치하거나 확정되지 않은 요구사항이 있으면 해당 요청을 보완한 뒤 다시 대조한다.
   자리표시자를 실제 값으로 채우고 승인 요청 전 검사를 통과한 응답을 반환한다.
5. 대응 기록이 없으면 기록 없음과 사유를 남기며 같은 확정 답을 재사용한다.
   권한은 기존 단계와 확정 답 판정으로 결정한다.
6. 같은 사용자 턴에 승인 요청을 다시 쓰면 양식 출력을 다시 확인하고 해당 절 전체를 보완한다.
   새 전체 승인 요청은 이전 보고를 대체하며 같은 기준으로 대조한다.

## Template

승인 종류에 맞는 생성기 출력의 제목과 필드를 사용한다.
구현 승인 요청은 양식 대신 아래 한 줄을 쓴다.

## 결과물 예시

e.g. 작업 `20261116-060912-agent-api`의 구현 승인 요청

```text
구현 승인 요청: 20261116-060912-agent-api
```

## 출력 검사

- 대상: 응답
- 필수: `(?m)^(?:#{1,2} (?:조사|모델 호출 실측|완료) 승인 요청|구현 승인 요청: \d{8}-\d{6}-[a-z0-9-]+)$` 승인 종류 양식의 제목이나 구현 승인 요청 줄을 쓴다.
- 금지: `approval-plan|계획 승인 요청` 계획은 구현 승인 요청으로 확정한다.
- 금지: `근거 출처` 출처 표기는 출처: 형식으로 쓴다.
- 금지: `(?m)^- (?:미확인|미검증|미완료|미측정)` 한계와 위험에는 설계 제약, 외부 이슈의 조건과 영향, 사후 실측 계획을 쓴다.
