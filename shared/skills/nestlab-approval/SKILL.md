## 승인 요청 절차

1. 승인 종류에 맞는 양식을 읽는다.
   - 조사 승인: 생성기의 `--print-template approval-research` stdout
   - 구현 승인: 생성기의 `--print-template approval-implement` stdout
   - 모델 호출 실측 승인: 생성기의 `--print-template approval-measure` stdout
2. 사용자가 요구를 바꾸거나 새 지시를 준 턴에 확정된 내용과 확인할 사실을 구분해 작업 문서에 반영한다.
3. 양식의 각 절에 변경 묶음 하나의 내용을 채우고 제목과 필드를 따른다.
   - 지침 문구 변경과 예상되는 표시나 결과의 변경 전후는 실제 원문과 대조한 unified diff로 붙인다.
   - 문구를 바꾸지 않고 위치만 옮기는 줄은 원본 절, 행과 이동 위치의 대조표로 붙인다.
4. 구현 승인 요청은 명세의 확정 요구사항과 양식의 필드를 대조한다.
5. 번호와 이름 및 확정 결과를 명세와 대조하고 모든 필수 값과 작업 문서 링크를 확인한다.
   불일치하거나 미확정인 요구사항이 있으면 해당 요청을 보완한 뒤 다시 대조한다.
   자리표시자를 실제 값으로 채우고 승인 요청 전 검사를 통과한 응답을 반환한다.
6. 대응 기록이 없으면 기록 없음과 사유를 남기며 같은 확정 답을 재사용한다.
   권한은 기존 단계와 확정 답 판정으로 결정한다.
7. 같은 사용자 턴의 Stop 재작성은 안내한 제목과 필드를 포함한 해당 절 전체를 보완한다.
   새 전체 승인 요청은 이전 보고를 대체하며 새로운 요청도 같은 기준으로 대조한다.

## Template

승인 종류에 맞는 생성기 출력의 제목과 필드를 사용한다.
구현 승인 요청의 필드 대응은 아래 정상 예시와 같이 작성한다.

## 결과물 예시

e.g. 명세의 확정 요구사항 `9. 사건 감지 알림`에 대한 구현 승인 요청

```markdown
# 승인 요청

## 관련 요구사항

- 요구사항 9. 사건 감지 알림: 감지 표현을 괄호 안에 나열하고 사건 문서 링크와 응답 지시를 표시한다. (근거: 요구사항 9)
  - 이번 변경: 알림의 두 줄 형식을 맞추고 감지 표현의 중복을 제거한다. (근거: 요구사항 9)

감지 패턴과 사건 문서의 감지 기록 및 응답 발췌 저장을 유지한다.
감지 패턴의 문맥 오판은 기존 제외 범위이다.

## 사전 작업

해당 없음

## 구현 요약

사건 감지 hook이 감지 표현을 중복 없이 나열하고 사건 문서 링크와 응답 지시를 정해진 두 줄 형식으로 출력하도록 변경한다. 두 runner의 reason과 systemMessage가 영향을 받는다.

## 저장소 영향

- hook: 사건 감지 hook의 reason과 systemMessage 출력
- 스킬: 없음
- 다른 역할: 없음
- Codex 경로: Codex Stop hook의 같은 출력

## 명세 문서

- [사건 감지 알림 명세](log/task/20261110-015333-director-stage-permissions/spec.md)
```
