# 승인 요청

## 승인 요청 절차

1. 조사 후 미확정 후보와 필요한 조사를 마친 추가 제안마다 명세 문서 검토 보고 절에 안 블록을 쓴 뒤,
   승인 요청 턴에 `검토 <번호>. <항목 이름>: <정할 대상>을 정한다.` 질문을 안 이름 선택지로 한 번 띄운다.
   후보가 하나여도 적용한다. 일반 확인, 요구사항 확정과 승인 명령은 각각 해당 절차로 처리한다.
2. 다음 확인 사항마다 충족 여부와 근거 위치를 대조한다.
   - 요구사항과 변경 근거가 저장소와 필요한 외부 조사로 확인되었다.
   - 문제 정의와 범위의 사용자 확인, 계획 단계의 요구사항 일괄 확정 및 후보 선택 기록이 있다.
   - 선택에 영향을 주는 잠재 위험과 한계를 보고하고 승인 요청에 반영했다.
   - 작업에 간접적 영향을 받는 파일이 전부 확인되고 작업 대상에 포함되었다.
3. 확인 사항 중 하나라도 충족되지 않으면 저장소 쓰기와 승인 요청을 보류한다.
4. 하단 `Template` 절 양식을 복사하고 각 절에 변경 묶음 하나의 내용을 채운다.
5. 완성한 응답을 양식과 대조해 각 절의 본문과 작업 문서 링크를 확인한다.
6. 문구 변경의 diff와 위치 이동의 원본 절, 행 및 이동 위치 대조표를 승인 요청 규칙과 대조한다.
7. 승인 재요청도 완성한 응답 전체를 같은 기준으로 대조한 뒤 반환한다.

## 승인 요청 규칙

- 사용자가 요구를 바꾸거나 새 지시를 준 턴에 확정된 내용과 확인할 사실을 구분해 작업 문서에 반영한다.
- 사전실측과 사후실측은 실행 전에 대상, 방법, 횟수와 예상 비용을 보고하고 승인받는다.
- 승인 요청 조건을 모두 채운 경우에만 같은 턴에 승인 요청을 띄운다.
- 검토 질문은 한 번만 띄우고, 선택 없이 넘기면 다음 사용자 메시지를 기다린다.
- 지침 문구 변경과 예상되는 표시나 결과의 변경 전후는 실제 원문과 대조한 unified diff로 붙인다.
- 문구를 바꾸지 않고 위치만 옮기는 줄은 원본 절, 행과 이동 위치의 대조표로 붙인다.
- 검증 계획의 명령은 적용 후 실행한다.

## Template

```markdown
# 승인 요청

<!-- 작업 문서를 작성한 경우 각 문서 경로 링크를 포함한다. -->

## 관련 요구사항

<!-- 사용자가 확정한 작업 관련 요구사항을 작성한다. -->

- 요구사항 <번호>. <요구사항 이름>: <변경 내용 한 문장>

<후보 선택 때 보고한 구현 한계와 잠재적 위험 요약 문단>

## 사전 작업

<!-- 구현 전 사전 수행 작업은 아래 내용을 작성한다. -->

<작업 요약 1문장>

- <작업 내용>
  - 목적: <목적>
  - 절차: <절차>
  - 발생 가능한 상황: <내용>

## 구현 작업

<!-- 구현 작업은 아래 내용을 작성한다. -->

<생성, 변경, 삭제 내용과 간접 영향을 받는 파일의 작업 요약 문단>

- `<대상 파일 경로>`
  - 목적: <목적>
  - 범위: <범위>

## 완료 기준

- <요구사항으로부터 파생된 기준 항목>

## 검증 계획

<!-- 검증이 필요없는 작업은 하단 내용 대신 판단 근거만을 작성한다. -->

- <검증 목적>: <테스트 파일명 또는 명령어>
- <실측 목적>: 대상 <실측 대상>, 방법 <실측 방법>, 비용 <실측 횟수 및 예상 비용>
```
