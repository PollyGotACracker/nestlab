# 승인 요청

## 절차

1. 승인 요청 전에 아래 두 조건을 확인한다.
   - 사용자 마지막 메시지의 지시, 요구 변경, 질문을 작업 문서와 응답에 모두 반영했다.
   - 아래 확인 질문 4개에 모두 `예`로 답할 수 있다.
     - 모든 요구사항과 작업 항목이 저장소, 외부 조사 전부 확인되고 사용자에게 검토되었는가?
     - 모든 잠재적인 위험 사항이 사용자에게 검토되었는가?
     - 모든 제안이 사용자로부터 승인 또는 기각되었는가?
     - 작업에 간접적 영향을 받는 파일이 전부 확인되고 작업 대상에 포함되었는가?
2. 하나라도 `아니요`면 저장소 쓰기를 금지하고 승인 요청을 보류한다.
   사용자가 요구를 바꾸거나 새 지시를 준 턴에는 반영 결과만 보고하고, 승인 요청은 조건을 채운 다음 턴에 띄운다.
3. 승인 요청 턴에 미확정 검토 항목을 모아 확정 질문을 한 번 띄우고, 확정 선택지 라벨에 `확정`을 넣는다.
   사용자가 선택 없이 넘긴 확정 질문은 다시 띄우지 않고 다음 사용자 메시지를 기다린다.
4. 승인 요청은 변경 묶음 하나로 쓰고 `Template` 절 양식을 따른다.
   - 지침 문구 변경과 예상되는 표시나 결과의 변경 전후는 실제 원문과 대조한 unified diff로 붙인다.
   - 검증 계획의 명령은 적용 후 실행한다.

## Template

```markdown
# 승인 요청

<!-- 작업 문서를 작성한 경우 각 문서 경로 링크를 포함한다. -->

## 관련 요구사항

<!-- 사용자가 검토 완료한 작업 관련 요구사항을 작성한다. -->

- 요구사항 <번호>. <요구사항 이름>: <변경 내용 한 문장>

<사용자가 검토 완료한 구현 한계, 잠재적 위험 요약 문단>

## 사전 작업

<!-- 구현 전 사전 수행 작업은 아래 내용을 작성한다. -->

<작업 요약 1문장>

- <작업 내용>
  - 목적: <목적>
  - 절차: <절차>
  - 발생 가능한 상황: <내용>

## 구현 작업

<!-- 구현 작업은 아래 내용을 작성한다. -->

<생성, 변경, 삭제 내용과 간접 영향을 받는 파일의 작업 요약 문단>

- `<대상 파일 경로>`
  - 목적: <목적>
  - 범위: <범위>

## 완료 기준

- <요구사항으로부터 파생된 기준 항목>

## 검증 계획

<!-- 검증이 필요없는 작업은 하단 내용 대신 판단 근거만을 작성한다. -->

- <검증 목적>: <테스트 파일명 또는 명령어>
- <실측 목적>: 대상 <실측 대상>, 방법 <실측 방법>, 비용 <실측 횟수 및 예상 비용>
```
