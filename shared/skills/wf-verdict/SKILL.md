# 검수 지적 판정

## 인수

- `검수`: 판정할 지적이 담긴 검수 결과
- `구현`: 구현 담당이 반환한 결과물 경로와 구현 근거
- `기준`: 입력 문서 위치. 이 문서에는 요구사항, 확정 결정(바꿀 수 없는 결정과 제약), 변경 범위 절이 있다.

## 지적별 판정

검수 결과의 지적마다 그 근거와 `구현`의 구현 근거를 결과물에서 직접 확인해 아래 중 하나로 판정한다.

- 근거 누락: 지적에 근거가 빠졌다.
  재검수에 필요한 항목과 근거를 적는다.
- 제외: 지적이 사실과 다르다.
  반증 근거를 기록한다.
- 위반: 지적이 사실이고, 요구사항과 규칙을 지키며 해결할 수 있다.
- 중단: 아래 `중단 유형` 절의 유형에 해당한다.

판정은 아래 기준을 지킨다.

- 설명 방식과 분량이 달라도 같은 요구사항·규칙·결과물·실행 근거에는 같은 판정 기준을 적용한다.
- 판단 전제마다 확인 근거를 연결하고, 미확인 전제는 판단 근거에서 분리한다.

## 중단 유형

위반을 재작업으로 넘기기 전에 아래 유형에 해당하는지 먼저 확인한다.
해당하면 그 작업과 종속 작업을 중단 대상으로 판정한다.

- 충족 불가: 요구사항과 규칙을 모두 지키는 결과물을 만들 수 없다.
- 선택 필요: 규칙을 지키는 방법이 둘 이상이고 선택이 사용자 선호에 달렸다.
- 해석 분기: 요구사항·규칙의 해석이 둘 이상이고 해석에 따라 결과물이 달라진다.
- 확정 변경: 위반 해소에 요구사항·규칙·확정 결정의 변경이 필요하다.
- 지속성 영향: 변경이 기존 클라이언트 사용에 영향을 주고, 사용자가 그 영향을 승인한 결정이 아직 없다.

## 수정 방식 선택

- 계속 가능한 위반은 수정 위치와 기대 결과를 독립 확인해 정한다.
- 수정 방식이 여러 개이면 변경 파일, 동작, 출력, 검증 명령 결과가 모두 같은 경우에만 이 Skill을 부른 쪽이 고른다.
  고른 내용은 바로 다음 사용자 보고에 별도 항목으로 알린다.
- 변경 파일, 동작, 출력, 검증 명령 결과 중 하나라도 다르면 `선택 필요`로 판정한다.

## 반환

- 지적마다 판정, 근거, 수정 위치와 기대 결과를 반환한다.

## 판정 예시

e.g. 기존 범위 해결

```markdown
- 구현 근거: 타입 단언 생략 시 코드 복잡도 증가
- 검수 결과 근거: 타입 단언 대신 type guard만 허용하는 TypeScript 제약의 규칙 위반. type guard로 요구사항을 충족할 수 있음
- 처리: 해당 위반을 확정된 범위 안의 재작업 대상으로 판정하고 구현 담당에게 수정을 요청한다.
```

```markdown
- 요구사항: 주문 생성 시 주문 항목 금액의 합계를 계산해 저장한다.
- 구현 근거: 합계 계산 함수는 요청 검증 함수 `validateOrderRequest`를 통과한 주문만 받으며, 검증 함수가 주문 항목이 null이거나 비어 있으면 요청을 거부함
- 검수 결과 근거: 합계 계산 함수에 주문 항목이 null일 때의 처리가 없어 경계 상태 처리 누락
- 처리: 검증 함수에서 null이 차단되는 것을 코드로 확인해 해당 지적을 위반에서 제외하며, 나머지 검수 항목은 별도로 판정한다.
```

e.g. 사용자 판단 필요

```markdown
- 구현 근거: 외부 SDK 타입 정의 때문에 현재 제약을 유지한 구현으로 요구사항 충족 불가
- 검수 결과 근거: 타입 단언 대신 type guard만 허용하는 TypeScript 제약의 규칙 위반
- 처리: 충족 불가로 중단하고 사용자 검토를 요청한다.
```

```markdown
- 요구사항: 구버전 앱 지원 종료에 따라 회원 목록 API 응답에서 구버전 앱만 사용하던 `legacyId` 필드를 제거한다.
- 구현 근거: 요구사항에 따라 회원 목록 API 응답에서 `legacyId` 필드를 제거함
- 검수 결과 근거: 응답 필드 삭제로 이 필드를 읽는 기존 클라이언트의 서비스 사용에 영향이 있음
- 처리: 기존 클라이언트의 필드 사용 종료가 미확인이므로 지속성 영향으로 중단하고 사용자 검토를 요청한다.
```
