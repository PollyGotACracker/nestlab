# 지침과 Skill 설계

## 1. 작업 구분

- 에이전트는 웹 검색과 작성 전에 대상과 작업을 내부적으로 판단하고 해당 절차를 적용한다.
  - 지침은 공통 행동이나 특정 역할의 행동 규칙을 담은 AGENTS.md, CLAUDE.md 문서이다.
  - Skill은 특정 작업의 입력, 수행 절차, 결과물과 완료 기준을 다루는 SKILL.md 문서이다.
  - 대상 문서는 지침과 Skill을 함께 가리킨다.
  - 생성은 새 문서를 작성하는 작업이다.
  - 수정은 기존 문서의 원문을 기준으로 요청한 부분을 고치는 작업이다.
- 생성은 같은 목적의 기존 대상 문서를 검색하고 신설, 개정, 통합 중 필요한 처리를 정한다.
- 수정은 기존 원문과 미커밋 변경을 확인하고 변경 대상과 보존할 내용을 정한다.

## 2. 웹 근거 확인

- 생성과 수정 모두 작성 전에 대상에 맞는 웹 검색과 원문 확인을 수행한다.
- 지침은 해결하려는 문제, 적용 상황, 목표를 검색어로 삼아 관련 웹 문서를 확인한다.
  확인한 문제의 조건과 대응 근거를 작성할 규칙에 연결한다.
- Skill은 그 Skill이 만들거나 수정할 결과물의 종류와 용도를 검색어로 삼아 실제 공개 결과물을 찾아 원문을 확인한다.
  - 실제 결과물의 구성과 내용을 확인하고 수행 절차와 완료 기준에 연결한다.
  - Skill 작성법 문서는 보조 근거로 사용하며 실제 결과물 확인은 별도로 수행한다.
    e.g. README 작성 Skill은 실제 공개 저장소의 README를, 포트폴리오 글 작성 Skill은 실제 게시글을 확인한다.
- 관련 자료가 부족하면 검색한 범위와 부족한 항목을 밝히고 사용자 요구와 확인한 근거를 구분한다.

## 3. 근거 문서 확인

- 작업 구분과 웹 근거 확인 절차를 적용하고 대상의 설계 근거 문서를 확인한다.
  - 참조 가능한 지식 저장소가 있는 경우 저장소를 검색해 근거 문서를 탐색한다.
  - 위키 검색 절차가 정해진 경우 해당 절차를 적용한다.
  - 찾은 근거 문서의 원문을 확인하고 관련 항목과 변경 근거를 연결한다.
  - 규칙 제안은 적용 대상 범위를 사용자 작업 전체와 대조한다.
  - 제안 응답의 첫머리에 기존 규칙 검색어와 일치한 `파일:행` 또는 일치 없음을 적는다.

## 4. 배치 결정

### 처리 결정

- 유지·개정·통합·신설 중 필요한 처리를 결정한다.
  - 사실과 설계 해석을 구분하고 변경 근거와 정의 위치를 연결한다.
- 같은 작업을 다루는 기존 지침과 Skill이 있으면 해당 문서의 개정·통합을 우선 검토한다.
  - 서로 다른 파일이더라도 같은 대상에 주입되는 유사한 규칙은 한 파일에만 둔다.

### 배치 위치

- 모든 세션에 적용하는 규칙은 공통 지침에 둔다.
- 특정 역할에만 적용하는 규칙은 역할 지침에 둔다.
- 특정 작업에만 적용하는 절차·예시는 Skill 원본에 둔다.
- 동일한 의미나 내용은 하나의 파일에 정의한다.
  작업할 대상 문서의 주제, 기능과 주입 시점을 먼저 고려한다.

### 외부 참조

- 외부 파일을 참조해야 할 경우 공통 지침의 `경로 목록` 정의만을 사용한다.
  - 외부 파일은 경로 목록의 이름까지만 적고, 필요한 규칙은 그 문장 안에서 완결한다.
  - 같은 파일 안의 절 참조는 허용한다.
- 대상 문서에서 대상에 구체적인 명칭이 있으면 경로 대신 그 명칭을 쓴다.
- Skill 본문에 다른 Skill명이나 특정 파일 경로를 제외한다.

## 5. 작성

- 적용 조건·수행 행동·확인 가능한 완료 기준을 긍정형으로 작성한다.
  - `중요한`, `쉬운`, `긴` 등 판정 기준이 없는 표현을 제거하고 구체적인 기준을 들어 작성한다.
  - 제한이 필요한 규칙은 허용 대상·적용 조건·대안 행동으로 작성한다.
  - 대상 문서의 문장 작성 또는 다른 역할 전달 전 부정 어미와 문장 길이를 검사한다.
  - 예시 템플릿은 서식 지침을 준수한다.
  - 대상 문서에 넣을 제안 문구는 파일에 쓸 때와 같은 서식으로 대화에 제시한다.
  - 대상 문서를 바꾸면 하네스가 경로·절 참조·다른 지침 참조·부정형을 자동 검사한다.
    보고된 위반은 모두 고친다.
- 같은 대상에는 같은 용어를 사용한다.
- 시점에 따라 바뀌는 정보는 현행 방법과 이전 방법으로 구분해 기재한다.

### 지침

- 지침 본문은 에이전트를 역할 이름으로 작성한다.
  에이전트 이름은 호출 식별자가 필요한 frontmatter의 `name`·`tools`에만 쓴다.

### Skill

#### 프론트매터

- `name`: 영문 소문자·숫자·하이픈으로 64자 이하로 작성한다.
- `description`: 사용 시점 정보를 배치한다.
  - 검증에는 호출 대상 요청과 비대상 요청을 함께 작성한다.
  - 비대상 요청은 키워드가 겹치지만 다른 작업이 필요한 요청으로 선정한다.

#### 본문

- 본문은 500줄 이하로 작성한다.
  Skill에 필요한 내용은 Skill 본문에 모두 둔다.
- Skill 본문은 역할 이름 대신 작업 대상과 결과물로 대상을 가리킨다.
  Skill이 다룰 대상과 기준은 본문 절차에서 요청과 작업 문맥으로 확인하게 쓴다.
- Skill 본문에 넣는 참고 문서는 스키마 관련 공식 문서로 한정한다.

## 6. 대조

- 대표 적용·비적용 사례와 변경된 요구사항을 연결해 대조한다.
  - 대상·근거·기존 문구·개정 문구·적용 사례를 보고한다.
    미확인 사항은 보고 전에 조사로 확인하거나 사용자 질문으로 바꾼다.
- 서식 지침과 결과물을 대조하여 지침을 위반한 내용을 수정한다.

## 7. 제출 확인

- 제안 제출 전 1~6단계 수행 여부를 확인한다.
