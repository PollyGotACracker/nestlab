# 지침과 스킬 설계

## 1. 현황 파악

- 지침, 스킬 문서를 전수조사하여 확인하고 신설, 개정, 통합 중 필요한 처리를 정한다.
- 기존 원문과 미커밋 변경을 확인하고 변경 대상과 보존할 내용을 정한다.

## 2. 웹 근거 확인

- 생성과 수정 모두 작성 전에 대상에 맞는 웹 검색과 원문 확인을 수행한다.
- 지침은 해결하려는 문제, 적용 상황, 목표를 검색어로 삼아 관련 웹 문서를 확인한다.
  확인한 문제의 조건과 대응 근거를 작성할 규칙에 연결한다.
- 스킬은 그 스킬이 만들거나 수정할 결과물의 종류와 용도를 검색어로 삼아 실제 공개 결과물을 찾아 원문을 확인한다.
  - 실제 결과물의 구성과 내용을 확인하고 수행 절차와 완료 기준에 연결한다.
  - 스킬 작성법 문서는 보조 근거로 사용하며 실제 결과물 확인은 별도로 수행한다.
    e.g. README 작성 스킬은 실제 공개 저장소의 README를, 포트폴리오 글 작성 스킬은 실제 게시글을 확인한다.
- 관련 자료가 부족하면 검색한 범위와 부족한 항목을 밝히고 사용자 요구와 확인한 근거를 구분한다.

## 3. 근거 문서 확인

- 작업 구분과 웹 근거 확인 절차를 적용하고 대상의 설계 근거 문서를 확인한다.
  - 참조 가능한 지식 저장소가 있는 경우 저장소를 검색해 근거 문서를 탐색한다.
  - 위키 검색 절차가 정해진 경우 해당 절차를 적용한다.
  - 찾은 근거 문서의 원문을 확인하고 관련 항목과 변경 근거를 연결한다.
  - 규칙 제안은 적용 대상 범위를 사용자 작업 전체와 대조한다.
  - 제안 응답의 첫머리에 기존 규칙 검색어와 일치한 `파일:행` 또는 일치 없음을 적는다.

## 4. 배치 선택

### 처리 선택

- 유지·개정·통합·신설 중 필요한 처리를 결정한다.
  - 사실과 설계 해석을 구분하고 변경 근거와 정의 위치를 연결한다.
- 같은 작업을 다루는 기존 지침과 스킬이 있으면 해당 문서의 개정·통합을 우선 검토한다.
  - 서로 다른 파일이더라도 같은 대상에 주입되는 유사한 규칙은 한 파일에만 둔다.

### 배치 위치

- 지침 및 스킬의 내용은 작성된 위치 및 실행되는 시점과 적절해야 한다.
- 모든 세션에 적용하는 규칙은 공통 지침에 둔다.
- 특정 역할에만 적용하는 규칙은 역할 지침에 둔다.
- 특정 작업에만 적용하는 절차·예시는 스킬 원본에 둔다.
- 동일한 의미나 내용은 하나의 파일에 정의한다.
  작업할 대상 문서의 주제, 기능과 주입 시점을 먼저 고려한다.

### 외부 참조

- 외부 파일을 참조해야 할 경우 프로젝트 전역 지침 `경로 목록` 정의만을 사용한다.
  - 외부 파일은 경로 목록의 이름까지만 적고, 필요한 규칙은 그 문장 안에서 완결한다.
  - 같은 파일 안의 절 참조는 허용한다.
- 대상 문서에서 대상에 구체적인 명칭이 있으면 경로 대신 그 명칭을 쓴다.
- 스킬 본문에 다른 스킬명이나 특정 파일 경로를 제외한다.

## 5. 작성

- 문장은 공백 포함 100자 내로 어순을 명확하게 작성한다.
- 전체 저장소 범위 내에서 다음을 통일해야 한다.
  - 서식 구조
  - 동일한 역할의 용어
  - 동일한 역할의 속성 또는 형식
- 기존 문서에서 현재 작업 목표와 충돌하는 요소를 발견하는 경우 현재 작업 기준으로 수정한 뒤 사용자에게 보고한다.
- 현재 저장소 범위 내에서 동일 내용의 재작성은 금지된다.
- 문장은 긍정형으로 작성한다.
- 구체적인 기준, 범위, 작업 절차를 포함해야 한다.
  - 적용 조건, 수행 행동, 확인 가능한 완료 기준을 작성한다.
  - `중요한`, `쉬운`, `긴` 등 판정 기준이 없는 표현을 제거하고 구체적인 기준을 들어 작성한다.
  - 제한이 필요한 규칙은 허용 대상, 적용 조건, 대안 행동으로 작성한다.
- 보고, 검토 목적의 응답 또는 문서 생성을 지시하는 경우 작성 템플릿이 포함되어야 한다.

### 지침

- 지침 본문은 에이전트를 역할 이름으로 작성한다.
  에이전트 이름은 호출 식별자가 필요한 frontmatter의 `name`·`tools`에만 쓴다.

### 스킬

#### 프론트매터

- `name`: 영문 소문자·숫자·하이픈으로 64자 이하로 작성한다.
- `description`: 사용 시점 정보를 배치한다.
  - 검증에는 호출 대상 요청과 비대상 요청을 함께 작성한다.
  - 비대상 요청은 키워드가 겹치지만 다른 작업이 필요한 요청으로 선정한다.

#### 본문

- 본문은 500줄 이하로 작성한다.
  스킬에 필요한 절차와 양식은 스킬 본문에 두고, 양식은 제목이 `Template`인 절의 코드 블록에 둔다.
- 스킬 본문은 역할 이름 대신 작업 대상과 결과물로 대상을 가리킨다.
  스킬이 다룰 대상과 기준은 본문 절차에서 요청과 작업 문맥으로 확인하게 쓴다.
- 스킬 본문에 넣는 참고 문서는 스키마 관련 공식 문서로 한정한다.

## 6. 대조

- 대표 적용·비적용 사례와 변경된 요구사항을 연결해 대조한다.
  - 대상·근거·기존 문구·개정 문구·적용 사례를 보고한다.
    미확인 사항은 보고 전에 조사로 확인한다.
  - 적용 사례의 동작 문장마다 재현 실행 결과나 같은 조건의 세션 기록 위치를 붙인다.
    붙일 근거가 없는 문장은 `[추론]` 태그와 확인 방법을 붙여 사실과 나눠 적는다.
- 서식 지침과 결과물을 대조하여 지침을 위반한 내용을 수정한다.

## 7. 제출 확인

- 제안 제출 전 1~6단계 수행 여부를 확인한다.
