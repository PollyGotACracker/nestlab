## 검증 절차

### 1. 기준 확인

1. 실제 변경 diff, 결과물, 원본과 요구사항이 지정한 기준 자료를 읽는다.
   검증 대상 파일은 읽기만 한다.
2. 다음 내용을 검증 목록에 적는다.
   - 요구사항별 검증 항목
   - 검증 계획의 커맨드
   - 잠재적 위험으로 예상한 구체적인 문제의 발생 여부
3. 운영 문서는 다음 확인 항목을 검증 목록에 추가한다.
   - 다른 문서와 절차, 커맨드, 설명이 중복되는지
   - 커맨드, 설정값과 동작 설명이 코드, 설정 파일 및 실행 결과와 일치하는지
   - 불가 사항과 제한 사항에 원인과 대안이 적혀 있는지
4. 재검증 항목이 지정되면 그 항목만 검증 목록에 남긴다.

### 2. 실행과 대조

1. 검증 계획에 지정된 대상 경로, 작업 디렉터리와 입력을 확인한다.
2. 해당 조건에서 tests 폴더의 모든 테스트와 검증 계획의 커맨드를 직접 실행한다.
3. 실제 동작을 확인해야 하는 항목은 해당 동작을 직접 실행한다.
4. 다음 내용을 기록하고, 문구 및 정적 설정 확인 결과와 실제 동작 실행 결과를 구분한다.
   - 실행 조건과 커맨드
   - 실행 결과와 실패한 항목 전체
   - 재현 불가 항목: 계획한 조건과 실제 조건의 차이, 재현 불가 사유와 확인 대안
5. 수치와 한도를 비교할 항목은 측정값과 설정값의 단위 및 적용 방식을 먼저 맞춘다.
6. 검증 목록의 각 항목을 결과물과 실행 결과에 대조한다.
7. 잠재적 위험으로 적은 문제가 실제로 발생했는지 확인한다.
8. 원본과 결과물을 비교해 요구사항 밖에서 변경한 내용을 기록한다.
9. 검증 목록에 없는 문제를 발견하면 `계획 밖 발견`으로 분류해 위치와 관찰 내용을 기록한다.

### 3. 판정과 반환

- 외부 런타임에 의존하는 항목은 공식 문서가 동작을 보장하거나 사후 모델 호출 실측으로 정상 동작을 확인한 경우에만 `PASS`로 기록한다.
- `계획 밖 발견`은 판정 대상과 구분한다.

1. 검증 목록의 각 항목과 요구사항 밖 변경을 다음 기준으로 판정한다.
   - `PASS`: 기준 충족
   - `FAIL`: 기준 미충족 또는 요구사항 밖 변경
   - `미측정`: 확인 결과 없음. 직접 실행해야 하는 항목은 실행 결과 없음
2. 판정마다 확인 위치와 관찰 내용 및 실행 결과를 근거로 적는다.
3. `미측정` 항목의 사유와 확인 대안을 적는다.
4. 결함마다 수정에 필요한 내용을 적는다.
   - 기존 요구사항과 변경 범위 안에서 수정 가능: 위치, 문제와 기대 결과
   - 요구사항, 확정 사항이나 제약 변경 필요: 변경할 항목과 근거
5. `미측정` 항목이 있으면 검증 상태를 미완료로 기록한다.
6. 다음 내용을 반환한다.
   - 검증 상태
   - 검증 목록 전체와 항목별 판정 및 근거
   - 결함 목록
   - `계획 밖 발견`
