# 결과물 검증

## 절차

### 1. 판정

1. 검증 기준으로 검증 목록을 만든다.
   - 검증 기준은 요구사항별 검증 항목, 검증 명령, 발생 여부를 확인할 위험이다.
   - 다시 검증할 항목이 지정되면 그 항목만 재검증한다.
   - 운영 문서 결과물: 아래 항목을 검증 목록에 넣는다.
     - 다른 문서와 같은 절차, 명령, 설명의 반복 여부
     - 명령, 설정값, 동작 서술과 해당 코드, 설정 파일, 실행 결과의 일치 여부
     - 불가 사항과 제한 사항 서술의 원인과 대안 포함 여부
2. 실제 변경 diff, 결과물, 원본, 요구사항이 지정한 기준 자료를 직접 연다.
3. 검증 항목마다 충족은 `PASS`, 미충족은 `FAIL`, 결과 없음은 `미측정`으로 판정하고 확인 위치와 관찰 내용을 적는다.
   `미측정` 항목이 있으면 검증을 미완료로 보고한다.
4. 원본과 결과물을 비교해 요구사항 밖 변경을 모두 `FAIL`로 기록한다.

### 2. 실행과 위험

1. 검증 계획의 검증 명령을 직접 실행하고, 명령과 결과를 판정 근거로 적는다.
   - 테스트를 바꾸거나 검증 명령을 실행할 때 해당 tests 폴더 전체를 실행하고 실패를 모두 보고한다.
   - 실제 동작 확인 항목은 완료 판정 전에 실행하고, 실행 결과가 없으면 `미측정`과 사유, 대안을 적는다.
   - 외부 런타임의 동작에 의존하는 판정은 그 동작이 공식 문서에 보장된 경우, 또는 사후실측 후 정상 동작을 확인한 경우에만 `PASS`로 기록한다.
2. 확인할 위험마다 실제로 발생했는지 확인한다.
3. 검증 항목, 검증 명령, 잠재적 위험에 없는 문제는 판정 대상에서 빼고 `계획 밖 발견`으로 위치와 관찰 내용만 적는다.

### 3. 결함과 반환

1. 검증 대상 파일은 고치지 않고 결함마다 처리 범위를 적는다.
   - 기존 범위에서 해결 가능: 위치, 문제, 기대 결과
   - 요구사항, 확정 사항, 제약 변경 필요: 변경 항목과 근거
2. 검증 목록 전체, 항목별 판정과 근거, 결함 목록, `계획 밖 발견`을 반환한다.
