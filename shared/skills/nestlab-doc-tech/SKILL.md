## 작성 절차

1. 기술과 범위를 확인한다.
   - 대상 기술, 버전, 기록 목적, 결과 위치(파일 또는 대화 초안)를 요청과 현재 세션의 대화에서 확인한다.
   - 다른 세션에서 다룬 기술이면 실행 중인 런타임의 세션 기록 파일을 기술 이름, 작업 ID나 핵심 용어로 검색해 걸린 세션을 시작 시각 순으로 읽는다.
     - 세션 기록 위치는 그 런타임의 공식 문서에서 확인하고, 공식 문서에 없으면 런타임 홈 폴더(`CODEX_HOME` 등) 아래에서 대화 기록 파일을 찾는다.
     - 압축된 기록 파일은 풀어서 검색한다.
     - 기록 파일이 어느 저장소의 세션인지는 파일 안의 작업 디렉터리 값으로 확인한다.
   - 기록 파일이 지워진 세션은 그 사실을 보고하고, 같은 작업의 기록 문서와 `git log`로 보충한다.
2. 외부 사실을 대상 버전의 공식 자료로 확인한다.
   - 공식 문서, 릴리스 노트, 이슈 트래커를 먼저 보고 블로그는 보조로만 쓴다.
   - 확인한 외부 사실에는 출처 링크를 단다.
3. 템플릿 항목을 모두 채운다.
   - 각 항목은 대상 버전에서 확인한 사실만 쓴다.
   - 자료로 채울 수 없는 항목은 사유와 함께 "확인 필요"로 둔다.
   - 비교 항목은 같은 기준으로 대상별 값을 나란히 적는다.
   - 개념 설명은 문서 이해에 필요한 최소 분량으로 쓴다.
4. 결과 위치에 쓰고 기록 위치와 내용을 반환한다.
   기존 파일이 있으면 본문을 보존하고 바뀌는 부분을 먼저 보여준다.

## Template

```markdown
# <기술 이름> <버전>

## 특징

- <핵심 특성>

## 개념

- <이해에 필요한 개념과 용어>

## 다른 기술과의 비교

| **기준** | **<이 기술>** | **<비교 기술>** |
| -------- | ------------- | --------------- |
| <기준>   | <값>          | <값>            |

## 주요 API

- `<이름>`: <용도와 시그니처>

## 제약과 이슈

- <제약, 알려진 이슈, 해결된 버전>

## 참고 자료

- [<자료 이름>](URL)
```
