# 사건 문서 양식

## 작성 시점

- hook이 직전 응답에서 실수·위반 인정 표현을 감지하면 사건 문서의 머리 항목과 `감지 기록` 절을 만든다.
- 이 Skill은 그 뒤 나머지 절을 채울 때 호출한다.
- 사건 문서는 어느 저장소 세션에서든 nestlab 저장소의 사건 문서 위치에 저장된다. `실행 위치`로 세션 cwd를 확인한다.

## 작성 규칙

- 직접 확인한 근거만 적는다.
- 사용자 결정과 요구의 출처는 세션 기록 id로 적는다.
  - id가 없으면 메시지를 받은 턴의 시각(KST)을 적는다.
- 시각(KST)은 `TZ=KST-9 date '+%Y-%m-%d %H:%M:%S'`로 확인한다.
- 확인하지 못한 항목은 `미확인`으로 표시한다.

## 절차

1. 오탐을 판정한다.
   - hook 지시문의 사건 문서 경로를 연다.
   - `감지 기록`의 감지 표현마다 오탐 여부를 판정한다.
   - 모두 오탐이면 근거를 `원인과 처리`에 적고 7단계로 넘어간다.
2. `사건 경과`를 채운다.
   - 세션 기록에서 요청, 기대 동작, 실제 결과, 수행 순서를 확인한다.
3. 외부 근거를 찾는다.
   - 원인과 예방 행동의 근거를 웹 검색한다.
   - 도구 기능에 의존하는 수단은 보편적인 사용법을 찾는다.
   - 출처 URL을 근거 칸에 적는다.
4. 원인을 특정한다.
   - 세션 기록과 관련 지침, Skill, hook, 설정 파일을 연다.
   - 실수를 허용한 결함을 `파일:행`으로 적는다.
   - 원인 유형: 규칙 충돌, 모호한 적용 조건, 검사 부재 등
5. `예방 행동`을 채운다.
   - 준수 기준, 해결 수단, 바꿀 `파일:행`, 후보 문구를 적는다.
   - 해결 수단: 지침, Skill, hook, 도구, 설정, 절차
   - 후보 문구와 같은 의미의 규칙을 같은 대상에 주입되는 문서에서 검색한다.
   - 중복과 충돌 결과를 후보 문구와 함께 적는다.
   - 기존 규칙을 어겼으면 그 규칙이 지켜지지 않은 원인을 바꾸는 수단을 적는다.
   - 여러 작업과 세션에 공통으로 적용되는 변경만 적는다.
   - hook은 다른 수단이 통하지 않을 때 택한다.
6. 상태를 갱신한다.
   - `조치 상태`를 갱신한다.
   - 같은 사건이 다시 일어났으면 `재발 기록`에 항목을 추가한다.
7. 응답을 다시 작성한다.
   - 원인, 예방 행동 제안, 출처, 사건 문서 경로를 요약한다.
   - 오탐이면 오탐 근거를 적는다.
   - 직전 응답 내용을 다시 작성한다.
