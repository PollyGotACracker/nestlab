# 사건 문서 양식

## 작성 시점

- hook이 직전 응답에서 실수 및 위반 인정 표현을 감지하면 사건 문서의 머리 항목과 `Template` 절의 감지 기록 절을 만든다.
- 신규 문서의 제목과 머리 항목 순서는 `Template` 절을 따른다. `runner` 값은 `claude` 또는 `codex`이다.
- 신규 사건 ID는 최초 감지 시각 `YYYYMMDD-HHMM`과 세션 ID 앞 8자를 하이픈으로 연결한다. 감지 시각은 hook 실행 환경의 현지 시각이며, 세션 ID가 없으면 `unknown`을 쓴다.
- 같은 감지일과 세션의 추가 감지는 기존 문서의 `감지 기록`에 누적한다. 날짜형 기존 문서를 먼저 확인하고, 시간형 기존 문서는 ID 순서로 정렬해 첫 문서를 선택한다. 기존 파일명, 제목, 머리 항목과 작성된 분석은 보존한다.
- 이 스킬은 그 뒤 나머지 절을 채울 때 호출한다.
- 사건 문서는 어느 저장소 세션에서든 nestlab 저장소의 사건 문서 위치에 저장된다. `실행 위치`로 세션 cwd를 확인한다.

## 작성 규칙

- 직접 확인한 근거만 적는다.
- 사용자 검토 결과와 요구의 출처는 세션 기록 id로 적는다.
  - id가 없으면 메시지를 받은 턴의 시각(KST)을 적는다.
- 시각(KST)은 `TZ=KST-9 date '+%Y-%m-%d %H:%M:%S'`로 확인한다.
- 확인하지 못한 항목은 `미확인`으로 표시한다.

## 절차

1. 현재 스킬 양식을 확인한다.
   - hook이 생성한 머리 항목과 감지 기록을 확인하고, 판정 결과에 따라 나머지 절을 작성한다.
2. 오탐을 판정한다.
   - hook 지시문의 사건 문서 경로를 연다.
   - 감지 표현, 전체 응답, 직전 사용자 요청을 함께 대조한다.
   - 표현의 오탐 여부와 실제 위반 여부를 각각 판정한다.
   - 모두 오탐이면 근거를 `원인과 처리`에 적고 7단계로 넘어간다.
3. `사건 경과`를 채운다.
   - 세션 기록에서 요청, 기대 동작, 실제 결과, 수행 순서를 확인한다.[확인 필요]
4. 외부 근거를 찾는다.
   - 원인과 예방 행동의 근거를 웹 검색한다.
   - 도구 기능에 의존하는 수단은 보편적인 사용법을 찾는다.
   - 출처 URL을 `외부 근거` 칸에 적는다.
5. 원인을 특정한다.
   - 세션 기록과 관련 지침, 스킬, hook, 설정 파일을 연다.
   - 실수를 허용한 결함을 `파일:행`으로 적는다.
   - 원인 유형: 규칙 충돌, 모호한 적용 조건, 검사 부재 등
6. `예방 행동`을 채운다.
   - 오탐이 아니라면 다음의 내용을 준수하여 작성한다.
     - 기존 시스템을 수정하지 않고 유지하도록 하는 제안은 제외한다.
     - 외부 근거가 포함되지 않은 제안은 제외한다.
   - 해결 수단: 지침, 스킬, hook, 도구, 설정, 절차
   - 후보 문구와 같은 의미의 규칙을 같은 대상에 주입되는 문서에서 검색한다.
   - 중복과 충돌 결과를 후보 문구와 함께 적는다.
   - 기존 규칙을 어겼으면 그 규칙이 지켜지지 않은 원인을 바꾸는 수단을 적는다.
   - hook은 다른 수단이 통하지 않을 때 택한다.
7. 상태를 갱신한다.
   - `조치 상태`를 갱신한다.
8. 양식과 작성한 내용을 대조한다.
9. 분석 결과를 최종 메시지로 반환한다.
   - 원인, 예방 행동 제안, 출처, 사건 문서 경로를 요약한다.
   - 오탐이면 오탐 근거를 적는다.

## Template

- 아래 코드 블록의 양식을 그대로 쓴다.
- 쓰기 검사 hook이 이 코드 블록의 제목을 필수 절로 검사한다.

```markdown
# <runner>: <사건 ID>

- 사건 ID: <사건-id>
- runner: <claude | codex>
- 세션 ID: <전체 세션 ID>
- 관련 작업 ID: <관련 작업 ID>
- 실행 위치: <세션 cwd | 미확인>
- 발생 및 확인 시점: <YYYY-MM-DD HH:MM:SS>
- 관련 담당: <사건을 발생시킨 담당>
- 조치 상태: <미착수 | 진행 | 완료>
```
