## 보고 절차

조사 결과만 반환하는 배정에서는 후보와 근거를 반환하고 사용자 선택은 조정 담당이 받는다.
아래 절차의 질문과 확정 기록은 사용자에게 후보를 보고하는 경우에 적용한다.

1. 보고할 검토 항목을 순서대로 놓는다. 전체 개수는 보고 시작 시점에 확정한 항목 수이다.
   - 다른 항목의 전제가 되는 항목을 앞에 둔다.
   - 추가 제안은 필요한 조사와 후보 설명을 갖춘 뒤 보고한다.
   - 사용자가 이미 판정한 사안은 새 근거가 생겼을 때만 다시 보고한다.
     다시 볼 때는 새 근거와 바뀌는 결론만 적는다.
2. 한 번에 한 항목만 보고하고 항목마다 선택을 따로 받는다.
   - 안은 3개 이하로 세우고, 문제를 해결하는 안만 세운다.
   - 요구나 확정 사항을 충족하지 못하는 안과 모든 판단 기준에서 다른 안보다 불리한 안은 `제외한 안`에 근거와 함께 적는다.
   - 후보 선택에 영향을 주는 잠재 위험과 한계는 선택 전에 보고하고 구현 승인 요청에도 반영한다.
3. 응답에는 생성기의 `--print-template request-choice` 출력 양식에 따라 조사 결과의 안 블록을 고치지 않고 쓰고 비교표를 더한다.
   - 보고 서두에 `## 검토 <번호> (<현재 개수>/<전체 개수>)` 제목을 쓴다. e.g. `## 검토 42 (2/3)`
   - 제목의 검토 번호는 질문 도구 질문의 검토 번호와 같은 값이다.
   - 비교표는 모든 안 이름을 행으로 두고 판단 기준별 충족 여부를 칸에 적는다.
   - 안 블록은 안마다 `#### 안 <번호>. <안 이름>` 제목으로 쓰고 `한계와 위험` 줄에 URL 출처를 붙인다.
   - 검토 근거는 응답에만 작성한다.
4. 응답 끝에 생성기의 `--print-template question-choice` 출력 양식의 질문을 질문 도구로 한 번 띄운다.
   - 질문은 마침표로 끝나는 서술문으로 쓰고 양식대로 확정된 문제 번호 괄호를 붙인다.
   - 선택지 라벨은 `안 <번호>. <안 이름>` 형식이고 안 번호 순서와 같다. 2~3개이다.
   - 요구와 확정 사항을 충족하는 안이 하나면 그 안과 제외한 안의 근거를 보고한 후, 선택지 `안 1. <안 이름>`, `폐기`, `재조사` 세 개를 띄운다.
   - 보류와 추가 조사는 선택지 없이 직접 입력으로 받고, hook은 이 답과 `재조사` 답을 기록에서 제외한다.
   - 수정은 질문 도구의 자유 입력으로 받는다.
   - 확정 답은 hook이 경과 문서의 검토 필요 절에 한 줄로 기록하고 명세의 요구사항 목록에 추가한다.
   - 질문 도구가 없는 환경에서는 같은 문장을 메시지로 묻는다.
