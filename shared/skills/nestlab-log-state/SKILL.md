# 경과 문서

## 작성 시점

- 착수 보고 때 director가 작업 상태 `미개시`로 만든다.
- 작업 경과, 결정 기록, 검증 결과는 해당 행동이 끝날 때마다 갱신한다.
- 작업 상태가 `중단`일 때만 `Template` 절의 중단 사유 절을 채운다.

## 작성 규칙

- 문서 위치는 프로젝트 전역 지침 경로 목록의 경과 문서이다.
- 칸의 `<...>` 자리표시자를 실제 값으로 바꾸고, 해당하지 않는 선택지는 지운다.
- 검증 결과가 없으면 작업 상태를 `완료`로 쓸 수 없다.
- 판정 칸은 칸 이름이 든 질문 도구의 확정 답이 있을 때만 쓴다.
  - 판정 칸은 검토 필요의 상태, 조사 문서의 확인 상태, 중단 기록이다.
  - 앞 단계 칸이 비어 있으면 hook이 판정 칸 쓰기를 거절한다.
- 검토 필요 항목의 `검토 완료`는 그 항목 이름으로 한 질문의 확정 답이 있을 때만 쓴다.
  사용자 답이 필요한 항목은 `사용자 검토 필요`로 둔다.
- 검토 완료 항목의 이름은 그대로 두고, 검토 완료가 아닌 항목만 이름을 바꾼다.
- hook이 덧붙인 `중단 판정 미해결` 줄은 그대로 보존한다.
- 요구사항 목록은 착수 보고 때 쓰고, 문제 정의의 처리 칸, 조사 문서 검토 항목, 명세 문서 요구사항은 이 번호를 쓴다.
- 착수 승인 상태와 실행 승인 상태는 처음 작성할 때 `승인 대기`로 쓴다.
- 원인 분석에는 원인 후보의 적용 조건과 당시 요청을 대조한 결과 및 실제 적용 증거를 구분해 기록한다.
- 결정 기록은 결정마다 `###` heading 하나를 둔다.
  - 담당, 결정, 근거 칸은 각각 한 문장으로 쓴다.
  - 한 문장에 담기 어려운 내용은 그 칸 아래 하위 목록으로 나눠 쓴다.
- 사용자 메시지는 핵심만을 요약한다.
- 근거 출처에 쓰는 `파일:행`은 다른 문서에서 옮겨 온 것이라도 쓰기 전에 그 파일을 열어 해당 행을 확인한다.
- 작업 ID 형식: `<YYYYMMDD-HHMMSS>-<영문 kebab-case 이름>`
- 시각 형식: `<YYYY-MM-DD HH:MM:SS>`

### 사용 커맨드

- 작업 ID 앞부분(KST): `TZ=KST-9 date '+%Y%m%d-%H%M%S'`
- 시각(KST): `TZ=KST-9 date '+%Y-%m-%d %H:%M:%S'`
- 기준 커밋: `git log -1 --format=%h`

## Template

- 아래 코드 블록의 양식을 그대로 쓴다.
- 쓰기 검사 hook이 이 코드 블록의 제목을 필수 절로 검사한다.

```markdown
# <작업명>

- 작업 ID: <작업-id>
- 작업 상태: <미개시 | 진행 | 중단 | 완료>

## 요구사항

### 요구사항 목록

1. <요구사항 이름>: <변경 내용 한 문장>

### 문제 정의

- <항목>: <관측 사실>
  - 근거 내용: <내용>
  - 근거 출처: <로그 시각 | 파일과 절 | 외부 링크>
  - 재현 절차: <재현 명령과 순서 | 해당 없음>
  - 처리: 요구사항 <번호>

### 원인 분석

- <항목>: <확인된 원인 | 미확인>
  - 근거 내용: <내용>
  - 근거 출처: <확인 위치 | 명령 결과>
  - 한계: <미확인 범위 | 기록 없음>

### 검토 필요

<!-- 사용자의 검토가 필요하거나 구현 후 잠재적인 위험이 있는 대상 목록 -->
<!-- 모든 목록이 검토 완료 또는 사후실측 필요일 때 승인 가능 -->

- <항목>
  - 상태: <미검토 | 사용자 검토 필요 | 사전실측 필요 | 사후실측 필요 | 검토 완료>
  - 사용자 검토 시각: <YYYY-MM-DD HH:MM:SS | 기록 없음>
  - 대응 근거: <근거 내용과 외부 조사 링크>
  - 대응 방안:
    - <작업 파일 경로>
    - <구체적인 작업 내용>

### 재검토 조건

<!-- 승인된 내용이나 요구사항이 변경될 수 있는 조건 -->

- <조건>

## 승인

### 착수 승인 범위

- 사용자 승인 상태: <승인 대기 | 승인>
- 사용자 승인 시각: <YYYY-MM-DD HH:MM:SS | 기록 없음>
- 연결 대상: 요구사항 <번호>
- 승인 행동: <승인된 행동>
- 영향 범위: <영향 대상과 제외 범위>
- 범위 밖: <승인에서 제외된 행동>

### 실행 승인 범위

- 사용자 승인 상태: <승인 대기 | 승인>
- 사용자 승인 시각: <YYYY-MM-DD HH:MM:SS | 기록 없음>
- 연결 대상: 요구사항 <번호>
- 승인 행동: <승인된 행동>
- 영향 범위: <영향 대상과 제외 범위>
- 범위 밖: <승인에서 제외된 행동>

## 작업 경과

- 갱신 시각: <YYYY-MM-DD HH:MM:SS>
- 진행 상황:
  - <현재 진행 상황 문장>
- 다음 작업: <다음 행동과 담당 | 기록 없음>

## 결정 기록

### <결정 이름>

- 시각: <YYYY-MM-DD HH:MM:SS>
- 담당: <에이전트 역할명>
- 결정: <한 문장>
- 근거: <한 문장>
  - <한 문장으로 부족할 때만 쓰는 하위 항목>

## 검증 결과

<검증 미개시 | 아래 항목>

- <YYYY-MM-DD HH:MM:SS>: <검증 항목> (요구사항 <번호>) (<정적 | 실제 동작>, <검증 | 재검증 n/2>)
  - <PASS | FAIL | 미측정>: <근거>
  - 결과물: <경로 | 마지막 검증 항목만>
  - 문서 갱신: <경로 | "검색어와 일치 없음" | 해당 없음 | 마지막 검증 항목만>
  - 남은 문제: <항목 | 없음 | 마지막 검증 항목만>

## 중단 사유

<작업 상태가 중단일 때만>

- 중단 유형: <충족 불가 | 선택 필요 | 해석 분기 | 확정 변경 | 지속성 영향>
- 중단 조건: <조건과 필요한 사용자 판단>
- 선택지
  1. <선택지>: <영향>
```
