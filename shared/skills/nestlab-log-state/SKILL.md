# 상태 문서 양식

## 작성 시점

- 착수 보고 때 director가 작업 상태 `미개시`로 만든다.
- 작업 경과, 작업 기록, 검수 결과는 해당 행동이 끝날 때마다 갱신한다.
- 작업 상태가 `중단`일 때만 `중단 사유` 절을 채운다.

## 작성 규칙

- 위치는 프로젝트 공통 지침 경로 목록의 상태 문서이다.
- 작업 ID는 `<YYYYMMDD-HHMMSS>-<영문 kebab-case 이름>`이고, 앞부분은 `TZ=KST-9 date '+%Y%m%d-%H%M%S'`로 만든다.
- 시각(KST)은 `<YYYY-MM-DD HH:MM:SS>` 형식이며 `TZ=KST-9 date '+%Y-%m-%d %H:%M:%S'`로 확인한다.
- 칸의 `<...>` 자리표시자를 실제 값으로 바꾸고, 해당하지 않는 선택지는 지운다.
- 사용자가 검수를 지시하지 않은 작업은 검수 결과에 `검수 미개시`를 적고 작업 상태를 `진행`으로 둔다.

## 양식

```markdown
# <작업명>

- 작업 ID: <작업-id>
- 작업 상태: <미개시 | 진행 | 중단 | 완료>

## 작업 경과

- 갱신 시각: <YYYY-MM-DD HH:MM:SS>
- 진행 상황:
  - <현재 진행 상황 문장>
- 다음 작업: <다음 행동과 담당 | 기록 없음>

## 작업 기록

- <YYYY-MM-DD HH:MM:SS>: <수행 내용>
  - 담당: <에이전트 역할명>
  - 결과: <결과와 근거>

## 검수 결과

- <YYYY-MM-DD HH:MM:SS>: <요구사항 이름> (<정적 | 실제 동작>, <검수 | 재검수 n/2>)
  - <PASS | FAIL | 미측정>: <근거>
  - 결과물: <경로 | 마지막 검수 항목만>
  - 문서 갱신: <경로 | "검색어와 일치 없음" | 해당 없음 | 마지막 검수 항목만>
  - 남은 문제: <항목 | 없음 | 마지막 검수 항목만>

## 중단 사유

<작업 상태가 중단일 때만>

- 중단 유형: <충족 불가 | 선택 필요 | 해석 분기 | 확정 변경 | 지속성 영향>
- 중단 조건: <조건과 필요한 사용자 판단>
- 선택지
  1. <선택지>: <영향>
```
