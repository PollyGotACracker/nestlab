# 저장소 탐색

## 절차

0. 진행 중인 작업의 조사 문서 `프로젝트 환경`과 입력 문서 `읽기 범위`가 있으면 먼저 읽는다.
   - 1~5단계에서 그 범위의 파일과 검색은 기록된 결과를 그대로 쓴다.
   - 변경, 누락, 충돌이 생긴 범위만 다시 확인하고 그 사유를 적는다.
1. 저장소 목적과 설계 구조를 확인한다.
   - README, 프로젝트 공통 지침의 경로 목록과 컨벤션, 운영 문서 목차를 우선 읽는다.
   - 폴더 구조와 빌드·설치 설정 파일로 구성 요소와 진입점을 찾는다.
   - README와 문서 서술은 코드와 설정으로 확인할 주장으로 다룬다.
   - 요청 대상이 속한 구성 요소와 그 구성 요소를 연결하는 설치 도구, hook 등록, 링크를 적는다.
2. 실행 환경을 확인한다.
   - 세션 실행 위치(cwd)와 역할을 확인한다.
   - 전역 폴더에 연결된 지침, 에이전트, Skill은 Agents 연결 도구와 Skill 연결 도구의 `check` 결과와 링크 대상으로 확인한다.
   - 다른 세션의 기록을 판정할 때는 그 기록의 실행 위치에서 열 수 있었던 경로와 주입된 지침으로 판정한다.
3. 대상을 탐색한다.
   - 1단계에서 찾은 구성 요소 안에서 요청 대상 파일과 그 동작·인터페이스 확인에 필요한 파일을 연다.
   - 확인 범위 지정이 없으면 파일 전체를 확인한다.
     큰 파일은 검색어, 기호, 행 범위로 나눠 읽고 빠지거나 잘린 부분만 추가로 읽는다.
   - 결론이 의존하는 정의, 연결 절차, 호출하는 쪽과 호출받는 쪽을 함께 읽는다.
   - 진입점부터 동작 하나를 끝까지 따라가 데이터 흐름을 확인한다.
   - 같은 기능의 구현이 여럿이면 현행, 이전, 생성물을 근거와 함께 구분한다.
   - 영향받는 운영 문서와 README를 본문 검색어로 검색해 일치한 `파일:행`과 검색어를 적는다.
     일치가 없으면 사용한 검색어를 적는다.
   - 파일을 옮기기 전 활성 참조와 링크의 실제 대상을 확인한다.
     기존 연결에 영향이 있으면 링크 갱신의 실행 가능 여부와 복구 방법을 확인한다.
4. 요청에 파일을 만들거나 바꾸는 작업이 있으면 기존 형식을 확인한다.
   - 같은 종류 기존 파일의 형식, 용어, 컨벤션을 확인한다.
     기존 컨벤션이 원칙과 충돌하면 작업 전 알린다.
   - 지침 문서는 같은 의미의 기존 규칙과 적용 조건, 행동, 판정 기준이 겹치는 위치를 검색한다.
   - 새 문서를 만들기 전 같은 작업을 다루는 기존 지침과 Skill을 검색한다.
5. 출처와 이력을 확인한다.
   - 설정과 권한 항목은 저장소 원본, 설치 도구 생성분, 사용자 항목 중 어디서 왔는지 `git log -S`와 설치 도구의 병합 규칙으로 확인한다.
   - 설치본과 원본의 차이는 원본끼리의 정책 차이와 다른 표로 나눠 적는다.
   - 과거 상태와 변경은 해당 시점의 원본과 기록(`git show <커밋>:<경로>`, `git log`)으로 대조한다.
   - 결함과 부재를 보고하기 전 대상 문서의 처리 규정과 실행 환경을 확인한다.
   - 로컬 상태는 실제 파일과 명령 결과로 확인한다.
6. 확인 범위를 기록한다.
   - 읽은 파일과 행 범위, 사용한 검색어, 검색에서 제외한 경로를 적는다.
   - 진행 중인 작업의 조사 문서가 있으면 확인한 저장소 사실과 확인 범위를 그 문서 `프로젝트 환경`에 추가한다.
     파일 쓰기 권한이 없는 세션은 결과의 확인 범위에 담아 반환한다.

## 결과

- 핵심 파일 표: 파일, 구성 요소에서의 역할, 근거 `파일:행`
- 확인한 사실과 추론의 구분
- 미확인 항목과 그 확인 방법
- 확인 범위
