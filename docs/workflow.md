# director 세션 워크플로

## 진행 순서

작업은 반드시 착수 단계부터 시작해야 하며, 이전 단계를 건너뛰어 진행할 수 없다.
단, 이전 단계로 되돌아가 재진행하는 것은 가능하다.
작업을 진행하기 어려운 상황에서 에이전트로부터 작업 중단 판정 요청이 오면 질문 도구에서 처리 방식을 고른다.

1. 새로운 작업은 `[kickoff]`, 기존 작업은 `[kickoff 작업ID]`로 문제 정의 시작을 전달한다.
2. 기초 조사 결과를 확인하여 논의 후 질문 도구로 문제 정의를 확정한다.
3. 조사 승인 요청을 확인한다.
4. `[research]` 또는 `[research 작업ID]`로 조사 진행 승인을 전달한다.
5. 검토 질문에서 구현 후보안을 확인하여 추가 논의 또는 확정한다.
6. 구현 승인 요청을 확인한다.
7. `[implement]` 또는 `[implement 작업ID]`로 구현 진행 승인을 전달한다.
8. 완료 승인 요청을 확인한다.
9. `[complete]` 또는 `[complete 작업ID]`로 작업 완료 결정을 전달한다.

## 단계 키워드

| **키워드**  | **단계** | **전달 시점**                                                                |
| :---------: | :------: | :--------------------------------------------------------------------------- |
|  `kickoff`  |   착수   | 새 작업 시작 / 현재 작업의 문제 재정의                                       |
| `research`  |   조사   | 기존 작업의 조사 시작 / 현재 작업의 조사 승인 요청 확인 / 현재 작업의 재조사 |
| `implement` |   구현   | 기존 작업의 구현 시작 / 현재 작업의 구현 승인 요청 확인 / 현재 작업의 재구현 |
| `complete`  |   완료   | 기존 작업의 완료 / 현재 작업의 완료 승인 요청 확인                           |

## 메시지 전달

- 단계 진입 시 메시지의 첫 단어로 `[키워드]` 또는 `[키워드 작업ID]`를 쓰고 본문을 이어서 쓴다.
- 작업 ID는 `YYYYMMDD-HHMMSS-kebab-case` 형식이며, 저장소 `log/task/<작업-id>/` 의 작업 문서 폴더명이다.
- 작업 진행 중 사용자 메시지의 첫 단어가 머리줄 형식이 아니면 작업 단계는 바뀌지 않는다.

### 신규 작업 시작

첫 작업을 시작할 때는 `kickoff` 키워드를 사용하여 다음과 같이 메시지를 전달한다.
세션의 첫 메시지가 키워드를 포함하지 않은 프로젝트 작업 요청이면서, 관련 작업 문서가 없다면 에이전트가 키워드를 사용할 것을 안내한다.

```text
[kickoff] 다음 로그를 분석해 오류의 원인과 발생 지점을 파악하고, 근거가 되는 로그 내용과 함께 구체적인 해결 방법을 확인해 주세요.
...
```

### 기존 작업 진행

기존 작업을 이어서 진행하려면 진행할 단계과 작업ID를 본문과 함께 작성한다.

```text
[implement 20261106-140000-example-task] 승인한 구현 계획대로 진행해주세요.
```

또는 작업ID만 입력하거나, 기존 작업을 이어서 진행하라고 지시할 수 있다.
에이전트가 지정된 해당 작업 문서 또는 최근 작업 문서의 작업 단계와 작업 경과(`status.md`)을 확인하여 진행한다.

```text
20261106-140000-example-task 진행해주세요.
```

```text
중단된 작업 이어서 진행해주세요.
```
