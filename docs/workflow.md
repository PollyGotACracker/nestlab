# 작업 단계 지정

## 머리줄 형식

- 메시지 첫 줄에 `[키워드]` 또는 `[키워드 작업ID]`만 쓰고 본문은 둘째 줄부터 쓴다.
- 작업 ID는 `YYYYMMDD-HHMMSS-kebab-case` 형식이다.
- 첫 줄이 머리줄 형식이 아니면 작업 단계는 바뀌지 않는다.

```text
[implement 20261106-140000-example-task]
승인한 구현 계획대로 진행한다.
```

## 단계 키워드

| **키워드**  | **단계** | **보낼 시점**                                  |
| :---------: | :------: | :--------------------------------------------- |
| `kickoff`   |   착수   | 새 작업을 시작하거나 문제와 범위를 다시 정할 때 |
| `research`  |   조사   | 조사 승인 요청을 확인한 뒤                     |
| `implement` |   구현   | 구현 승인 요청을 확인한 뒤                     |
| `complete`  |   완료   | 완료 승인 요청을 확인한 뒤                     |

## 진행 순서

1. `[kickoff]`로 작업을 시작하고 질문 도구로 문제 정의를 확정한다.
2. 조사 승인 요청을 확인하고 `[research 작업ID]`를 보낸다.
3. 검토 질문에서 후보 안을 고른다.
4. 구현 승인 요청을 확인하고 `[implement 작업ID]`를 보낸다.
5. 완료 승인 요청을 확인하고 `[complete 작업ID]`를 보낸다.

- 중단 판정 요청이 오면 질문 도구에서 처리 방식을 고른다.
- 작업 문서는 저장소의 `log/task/<작업-id>/`에 생성된다.
