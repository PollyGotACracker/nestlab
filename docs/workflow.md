# 작업 워크플로

이 문서는 director(Rio)와 프로젝트 작업을 진행하는 사용자를 위한 안내서이다.
작업은 `계획 → 구현 → 완료` 3단계로 진행한다.
계획과 구현 단계는 역방향으로 진행할 수 있으나, 신규 작업을 구현 단계부터 시작할 수는 없다.
작업 단계는 사용자가 메시지 처음에 '해당 단계의 키워드' 또는 메시지 끝에 '승인 키워드'로 전환한다.

## 작업 단계 키워드 입력

작업 ID와 작업 단계를 메시지의 첫머리에 작성한다.
`현재 진행 작업`은 작업 색인(`.agent-logs/task/index.md`)의 `현재 진행 작업` 절이다.
세션 작업은 `현재 진행 작업`이다. 다른 세션에서 `현재 진행 작업`을 바꾸면 이 세션의 대상 작업도 바뀐다.

| **작업**              | **입력**                                   |
| :-------------------- | :----------------------------------------- |
| 신규 작업 착수        | `[plan new]` 및 요청 본문                  |
| `현재 진행 작업` 인계 | 요청 본문 작성                             |
| 특정 작업 진행        | `[<작업 ID>]` 및 요청 본문                 |
| 세션 작업 추가 요청   | 요청 본문 작성                             |
| 세션 작업 계획 전환   | `[plan]` 및 요청 본문                      |
| 특정 작업 계획 전환   | `[plan <작업 ID>]` 및 요청 본문            |
| 세션 작업 구현 전환   | `[implement]` 및 요청 본문(선택)           |
| 특정 작업 구현 전환   | `[implement <작업 ID>]` 및 요청 본문(선택) |
| 세션 작업 완료 처리   | `[complete]` 및 요청 본문(선택)            |
| 특정 작업 완료 처리   | `[complete <작업 ID>]` 및 요청 본문(선택)  |

- 작업 ID가 작업 문서로 존재하지 않는 경우: 에이전트가 해당 작업이 문서로 존재하지 않음을 알린다.
- 작업 ID와 작업 단계를 전부 입력하는 경우: 해당 작업으로 진행되며 작업 단계가 변경된다.
- 작업 ID만 입력하는 경우: 해당 작업 및 문서에 표기된 작업 단계에 따라 진행되며 `현재 진행 작업`이 변경된다.
- 작업 단계만 입력하는 경우: `현재 진행 작업`의 단계 전환 요청으로 인식한다.
- 작업 ID와 작업 단계를 전부 생략하는 경우: `현재 진행 작업`이 인계되며 해당 작업의 추가 요청으로 인식한다.
- 작업 단계만 입력하거나 전부 생략했는데 `현재 진행 작업`이 없는 경우:
  에이전트가 해당 요청과 관련된 작업 목록을 표시하며 어떤 작업으로 진행할지, 또는 신규 작업으로 착수할지 질문한다.

```text
[implement] 검증 작업 끝나고 사후 실측 계획해.
```

## 승인 키워드 입력

승인 키워드는 다음 단계로의 이행, API 호출과 같은 비용 작업을 승낙한다.
구현 단계가 아닌 경우: 쓰기 작업의 승인 범위는 다음에 실행되는 1턴에 한정하여 적용된다.
이는 의도치 않은 에이전트의 파일 변경을 방지하기 위함이다.
구현 단계인 경우: 보안 문서 접근, 세션 경로 이탈, git 비가역 작업 외의 모든 작업이 자동으로 승인된다.
이는 불필요한 승인 절차를 없애기 위함이다.

| **작업**         | **입력**                |
| :--------------- | :---------------------- |
| 승인 요청에 동의 | 메시지 끝에 `승인` 추가 |

```text
검증 작업 끝나고 사후 실측 계획해. 승인.
```

메시지의 마지막을 `승인`으로 끝내면 승인으로 처리된다.
`승인` 뒤에는 `.`, `!`, `~`를 붙일 수 있다.
`승인` 바로 앞에 `안`이나 `못`을 쓰면 거절로 처리된다.

## 단계별 진행

모델 호출 비용이 드는 실측이 필요한 경우 에이전트가 실행 전 별도의 승인을 요청한다.

### 1. 계획 (`[plan]`)

조사, 실측부터 구현 계획까지 진행한다.

1. 관련 파일, 실행 환경과 외부 자료(공식 문서, 공개 구현, 이슈와 반대 자료)를 직접 조사하고 실측을 실행한다.
2. 문제가 정리될 때마다 질문 창으로 문제 정의 확정 또는 폐기, 수정을 요청받는다. 선택하면 해당 문제 정의로 반영된다.
3. 복수 대안 비교나 대량 조사가 필요하면 조사 승인을 요청받는다. 승인하면 각 서브에이전트가 조사-반증 작업을 수행한다.
4. 설계 후보가 나오면 보고와 함께 질문 창으로 선택을 요청받는다. 선택하면 해당 설계안으로 확정된다.
5. 마지막으로 구현 승인을 요청받는다. 이 요청을 승인하면 계획과 구현 범위가 함께 확정된다.

### 2. 구현 (`[implement]`)

실제 구현, 테스트 및 검증과 사후 실측까지 진행한다.
각 작업마다 서브에이전트가 배정되며, 간단한 작업은 메인에이전트가 직접 수행한다.

1. 승인된 요구사항의 구현 작업을 시작한다.
2. 결과물을 검증한다.
3. 결함을 판단하여 재작업을 시작한다.
4. 작업을 진행하기 어려운 상황에서 에이전트로부터 작업 중단 판정 요청이 오면 질문 도구에서 처리 방식을 고른다.

### 3. 완료 (`[complete]`)

요구사항별 검증 결과와 남은 문제를 정리해 완료 승인을 요청받는다.
승인하면 작업 문서에 완료 시각이 기록되고, 작업 색인 문서에서 해당 작업이 완료 작업 목록으로 옮겨진다.
